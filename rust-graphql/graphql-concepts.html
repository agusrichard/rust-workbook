GraphQL Concepts

A short introduction to what GraphQL is, why it exists, and when it is the right tool, with a first taste of it in Rust.

1. Background 2. Main concepts 3. Examples 4. In Rust 5. Usages 6. When to use it 7. Code reference

1Background

GraphQL is a query language for APIs. The client describes exactly what data it wants, and the server returns exactly that, in the same shape.

Facebook created it in 2012 while rebuilding its mobile app. Their REST APIs caused two recurring problems on slow mobile networks:

  • Over-fetching: an endpoint returns a full object when the screen needs only two fields.
  • Under-fetching: one screen needs several endpoints, so the app makes many round trips (user, then posts, then comments for each post).

GraphQL solved both by letting the client ask for everything a screen needs in one request. It was open-sourced in 2015 and is now maintained by the GraphQL Foundation as an open specification, with implementations in most languages, including Rust.

One-line mental model: REST gives you many URLs that each return a fixed shape. GraphQL gives you one URL and lets you choose the shape.

2Main concepts

Schema
The contract between client and server. It lists every type and every operation the API supports. Everything else builds on it.
Types and fields
Data is described as types (Book, Author) with fields (title, name). Fields can point to other types, which is what forms the "graph". A ! means the value is never null.
Query
A read operation. Similar to GET in REST.
Mutation
A write operation (create, update, delete). Similar to POST, PUT, DELETE.
Subscription
A long-lived stream of updates pushed from the server, usually over WebSocket.
Resolver
The function on the server that produces the value for one field. This is the code you actually write: each field in the schema maps to a resolver.
Single endpoint
All operations go to one URL, typically POST /graphql. The request body, not the URL, says what you want.

3Examples

A schema

type Book {
  id: ID!
  title: String!
  author: Author!
}

type Author {
  id: ID!
  name: String!
  books: [Book!]!
}

type Query {
  book(id: ID!): Book
  books: [Book!]!
}

type Mutation {
  addBook(title: String!, authorId: ID!): Book!
}

A query and its response

The response mirrors the query. Ask for two fields, get two fields.

Request

{
  book(id: "1") {
    title
    author {
      name
    }
  }
}

Response

{
  "data": {
    "book": {
      "title": "Dune",
      "author": {
        "name": "Frank Herbert"
      }
    }
  }
}

With REST this would usually be two calls: GET /books/1, then GET /authors/7.

A mutation

mutation {
  addBook(title: "Children of Dune", authorId: "7") {
    id
    title
  }
}

A mutation also returns data, so you can read back the object you just changed in the same request.

4In Rust

The most common Rust library is async-graphql (Juniper is the main alternative). You write plain Rust structs and methods, and the schema is generated from them.

use async_graphql::{EmptyMutation, EmptySubscription, Object, Schema, SimpleObject};

// A GraphQL type: each struct field becomes a GraphQL field.
#[derive(SimpleObject)]
struct Book {
    id: i32,
    title: String,
}

struct Query;

// Each method here is a resolver for a field on the Query type.
#[Object]
impl Query {
    async fn book(&self, id: i32) -> Option<Book> {
        (id == 1).then(|| Book { id, title: "Dune".into() })
    }
}

#[tokio::main]
async fn main() {
    let schema = Schema::new(Query, EmptyMutation, EmptySubscription);
    let res = schema.execute("{ book(id: 1) { title } }").await;
    println!("{}", serde_json::to_string(&res).unwrap());
    // {"data":{"book":{"title":"Dune"}}}
}

Notice how the concepts line up: the struct is a type, the method is a resolver, and Rust's Option<Book> becomes a nullable Book in the schema. Rust's type system and GraphQL's type system fit together well, which is a large part of why the pairing is pleasant.

5Usages

  • Mobile and web apps with many screens that each need a different slice of the same data.
  • API gateway / backend-for-frontend: one GraphQL layer in front of several microservices or databases, so clients see a single unified API.
  • Public developer APIs where consumers have needs you cannot predict (GitHub and Shopify both offer one).
  • Realtime features like chat, notifications, and live dashboards, via subscriptions.
  • Fast-moving frontends: the UI team can add a field to a query without waiting for a new backend endpoint.

6When to use it instead of other API styles

RESTGraphQLgRPC
Shape of dataFixed by serverChosen by clientFixed by server
EndpointsOne per resourceOneOne per method
ContractOptional (OpenAPI)Required schemaRequired (protobuf)
HTTP cachingEasy, built inNeeds extra workNot typical
Best atSimple, public, cacheable resourcesFlexible data for UIsFast service-to-service calls

Choose GraphQL when

  • Different clients need different views of the same data.
  • Your data is nested and connected.
  • Screens currently need several REST calls to render.
  • You want a typed, self-documenting API.
  • You are combining many backends behind one API.

Choose something else when

  • The API is small, simple CRUD: REST is less work.
  • You rely heavily on HTTP/CDN caching: REST.
  • You mostly serve file uploads or downloads: REST.
  • It is internal, high-throughput service-to-service traffic: gRPC.

Trade-offs to know about

  • N+1 queries: a list of 50 books that each resolve an author can trigger 51 database calls. The standard fix is batching with a DataLoader.
  • Expensive queries: clients can ask for deeply nested data, so servers usually set depth or complexity limits.
  • Errors look different: responses are typically 200 OK with problems listed in an errors array, rather than signalled by HTTP status codes.
  • More setup: a schema, resolvers, and tooling are overhead that a tiny API may not need.

Server and request handler

src/main.rs · Milestones 1, 8, 9

Reads the config, builds the schema, and maps three routes: the GraphiQL page, the query endpoint, and the WebSocket for subscriptions. Before authentication exists, the /graphql route can simply be .route_service("/graphql", GraphQL::new(schema)), with no state and no handler.

mod auth;
mod db;
mod models;
mod schema;
#[cfg(test)]
mod tests;

use async_graphql::http::GraphiQLSource;
use async_graphql_axum::{GraphQLRequest, GraphQLResponse, GraphQLSubscription};
use axum::{
    Router,
    extract::State,
    http::HeaderMap,
    response::{Html, IntoResponse},
    routing::{get, post},
};
use tokio::net::TcpListener;

use auth::JwtSecret;
use schema::AppSchema;

// Shared with every HTTP handler.
#[derive(Clone)]
struct AppState {
    schema: AppSchema,
    secret: JwtSecret,
}

async fn graphiql() -> impl IntoResponse {
    Html(
        GraphiQLSource::build()
            .endpoint("/graphql")
            .subscription_endpoint("/ws")
            .finish(),
    )
}

// Our own handler instead of the ready-made GraphQL service,
// so we can look at the headers before the query runs.
async fn graphql(
    State(state): State<AppState>,
    headers: HeaderMap,
    request: GraphQLRequest,
) -> GraphQLResponse {
    let mut request = request.into_inner();

    // Per-request data: only this request sees this CurrentUser.
    if let Some(user) = auth::user_from_headers(&headers, &state.secret) {
        request = request.data(user);
    }

    state.schema.execute(request).await.into()
}

#[tokio::main]
async fn main() {
    dotenvy::dotenv().ok(); // load .env if present

    let database_url = std::env::var("DATABASE_URL").expect("DATABASE_URL is not set");
    let secret = JwtSecret(std::env::var("JWT_SECRET").expect("JWT_SECRET is not set"));

    let pool = db::connect(&database_url).await.unwrap();
    let schema = schema::build_schema(pool, secret.clone());

    let app = Router::new()
        .route("/", get(graphiql))
        .route("/graphql", post(graphql))
        // Subscriptions use a WebSocket, served by a ready-made service.
        .route_service("/ws", GraphQLSubscription::new(schema.clone()))
        .with_state(AppState { schema, secret });

    let listener = TcpListener::bind("127.0.0.1:8000").await.unwrap();
    println!("GraphiQL: http://localhost:8000");
    axum::serve(listener, app).await.unwrap();
}

Connecting to SQLite

src/db.rs · Milestone 2

Opens a connection pool and applies the migrations. The pool is what every resolver uses to talk to the database.

use std::str::FromStr;

use sqlx::SqlitePool;
use sqlx::sqlite::SqliteConnectOptions;

pub async fn connect(url: &str) -> Result<SqlitePool, sqlx::Error> {
    // create_if_missing: make the .db file on first run.
    let options = SqliteConnectOptions::from_str(url)?.create_if_missing(true);
    let pool = SqlitePool::connect_with(options).await?;

    // Runs every file in ./migrations that has not been applied yet.
    sqlx::migrate!().run(&pool).await?;
    Ok(pool)
}

Types: objects, relations, inputs

src/models.rs · Milestones 2 to 5, 7, 8

Every type that appears in the GraphQL schema. Three kinds: output objects (SimpleObject), computed fields and relations on them (ComplexObject), and argument types (InputObject).

use async_graphql::{ComplexObject, Context, ID, InputObject, Result, SimpleObject};
use sqlx::{FromRow, SqlitePool};

// SimpleObject: every struct field becomes a GraphQL field.
// FromRow: sqlx can build this struct from a database row.
// complex: more fields are defined in the #[ComplexObject] block below.
#[derive(SimpleObject, FromRow, Clone)]
#[graphql(complex)]
pub struct Task {
    #[graphql(skip)] // hidden; re-exposed below as an ID
    pub id: i64,
    pub title: String,
    pub done: bool,
    #[graphql(skip)] // hidden; clients use `project` instead
    pub project_id: i64,
}

#[ComplexObject]
impl Task {
    // SQLite gives us an i64, GraphQL should show an ID.
    async fn id(&self) -> ID {
        self.id.into()
    }

    // A relation: not a column, but a query run when the field is requested.
    async fn project(&self, ctx: &Context<'_>) -> Result<Project> {
        let pool = ctx.data::<SqlitePool>()?;
        let project = sqlx::query_as("SELECT * FROM projects WHERE id = ?")
            .bind(self.project_id)
            .fetch_one(pool)
            .await?;
        Ok(project)
    }
}

#[derive(SimpleObject, FromRow, Clone)]
#[graphql(complex)]
pub struct Project {
    #[graphql(skip)]
    pub id: i64,
    pub name: String,
}

#[ComplexObject]
impl Project {
    async fn id(&self) -> ID {
        self.id.into()
    }

    // The same relation from the other side: one project, many tasks.
    async fn tasks(&self, ctx: &Context<'_>) -> Result<Vec<Task>> {
        let pool = ctx.data::<SqlitePool>()?;
        let tasks = sqlx::query_as("SELECT * FROM tasks WHERE project_id = ? ORDER BY id")
            .bind(self.id)
            .fetch_all(pool)
            .await?;
        Ok(tasks)
    }
}

// InputObject: a type clients send as an argument.
#[derive(InputObject)]
pub struct CreateTaskInput {
    pub title: String,
    pub project_id: ID, // projectId in GraphQL
}

// Option<T> = the client may leave the field out.
#[derive(InputObject)]
pub struct UpdateTaskInput {
    pub title: Option<String>,
    pub done: Option<bool>,
}

// One page of a list, plus what the client needs to ask for the next one.
#[derive(SimpleObject)]
pub struct TaskPage {
    pub items: Vec<Task>,
    pub total_count: i64,
    pub has_next_page: bool,
}

#[derive(SimpleObject, FromRow, Clone)]
#[graphql(complex)]
pub struct User {
    #[graphql(skip)]
    pub id: i64,
    pub username: String,
    #[graphql(skip)] // never leaves the server
    pub password_hash: String,
}

#[ComplexObject]
impl User {
    async fn id(&self) -> ID {
        self.id.into()
    }
}

#[derive(InputObject)]
pub struct CredentialsInput {
    pub username: String,
    pub password: String,
}

#[derive(SimpleObject)]
pub struct AuthPayload {
    pub token: String,
    pub user: User,
}

Assembling the schema

src/schema/mod.rs · Milestones 1, 2, 9

Puts the three root types together and registers the shared values that resolvers fetch with ctx.data::<T>(). Data is looked up by type, which is why the secret is wrapped in its own JwtSecret type.

mod mutation;
mod query;
mod subscription;

use async_graphql::Schema;
use sqlx::SqlitePool;
use tokio::sync::broadcast;

use crate::auth::JwtSecret;
use crate::models::Task;
use mutation::Mutation;
use query::Query;
use subscription::Subscription;

// A short name for the full schema type.
pub type AppSchema = Schema<Query, Mutation, Subscription>;

pub fn build_schema(pool: SqlitePool, secret: JwtSecret) -> AppSchema {
    // The channel that carries "task added" events to subscribers.
    let (events, _) = broadcast::channel::<Task>(16);

    // .data(...) makes a value available to every resolver through ctx.data::<T>().
    Schema::build(Query, Mutation, Subscription)
        .data(pool)
        .data(secret)
        .data(events)
        .finish()
}

Queries and pagination

src/schema/query.rs · Milestones 3, 7, 8

Reads. Note the three sqlx fetch methods: fetch_all for a list, fetch_optional for zero or one row, fetch_one for exactly one. The ? operator turns any error into a GraphQL error.

use async_graphql::{Context, Error, ID, Object, Result};
use sqlx::SqlitePool;

use crate::auth::CurrentUser;
use crate::models::{Project, Task, TaskPage, User};

pub struct Query;

#[Object]
impl Query {
    // A plain list.
    async fn projects(&self, ctx: &Context<'_>) -> Result<Vec<Project>> {
        let pool = ctx.data::<SqlitePool>()?;
        let projects = sqlx::query_as("SELECT * FROM projects ORDER BY id")
            .fetch_all(pool)
            .await?;
        Ok(projects)
    }

    // One item by id. Option = null when nothing matches.
    async fn task(&self, ctx: &Context<'_>, id: ID) -> Result<Option<Task>> {
        let pool = ctx.data::<SqlitePool>()?;
        let id: i64 = id.parse()?;
        let task = sqlx::query_as("SELECT * FROM tasks WHERE id = ?")
            .bind(id)
            .fetch_optional(pool)
            .await?;
        Ok(task)
    }

    // A paginated list. Arguments with defaults are optional for the client.
    async fn tasks(
        &self,
        ctx: &Context<'_>,
        #[graphql(default = 10)] limit: i64,
        #[graphql(default = 0)] offset: i64,
    ) -> Result<TaskPage> {
        if !(1..=50).contains(&limit) || offset < 0 {
            return Err(Error::new("limit must be 1 to 50 and offset 0 or more"));
        }
        let pool = ctx.data::<SqlitePool>()?;

        // A fixed ORDER BY keeps pages from overlapping.
        let items: Vec<Task> = sqlx::query_as("SELECT * FROM tasks ORDER BY id LIMIT ? OFFSET ?")
            .bind(limit)
            .bind(offset)
            .fetch_all(pool)
            .await?;

        // query_scalar: for a query that returns a single value.
        let total_count: i64 = sqlx::query_scalar("SELECT COUNT(*) FROM tasks")
            .fetch_one(pool)
            .await?;

        Ok(TaskPage {
            has_next_page: offset + (items.len() as i64) < total_count,
            items,
            total_count,
        })
    }

    // data_opt returns None when the request is anonymous.
    async fn me(&self, ctx: &Context<'_>) -> Result<Option<User>> {
        let Some(current) = ctx.data_opt::<CurrentUser>() else {
            return Ok(None);
        };
        let pool = ctx.data::<SqlitePool>()?;
        let user = sqlx::query_as("SELECT * FROM users WHERE id = ?")
            .bind(current.id)
            .fetch_optional(pool)
            .await?;
        Ok(user)
    }
}

Mutations, validation, and errors

src/schema/mutation.rs · Milestones 5, 6, 8, 9

Writes. Each one follows the same order: get the pool, parse the id, validate, run the SQL, return the result or a readable error.

use async_graphql::{Context, Error, ID, Object, Result};
use sqlx::SqlitePool;
use tokio::sync::broadcast;

use crate::auth::{self, JwtSecret, LoggedIn};
use crate::models::{AuthPayload, CreateTaskInput, CredentialsInput, Task, UpdateTaskInput, User};

pub struct Mutation;

#[Object]
impl Mutation {
    // ---- Create ----
    #[graphql(guard = "LoggedIn")] // rejects anonymous requests
    async fn create_task(&self, ctx: &Context<'_>, input: CreateTaskInput) -> Result<Task> {
        let pool = ctx.data::<SqlitePool>()?;
        let project_id: i64 = input.project_id.parse()?;

        // Validate the input.
        let title = input.title.trim();
        if title.is_empty() {
            return Err(Error::new("Title cannot be blank"));
        }

        // Check the parent exists, so the client gets a readable error.
        let exists: Option<i64> = sqlx::query_scalar("SELECT id FROM projects WHERE id = ?")
            .bind(project_id)
            .fetch_optional(pool)
            .await?;
        if exists.is_none() {
            return Err(Error::new(format!("Project {project_id} not found")));
        }

        // RETURNING hands back the row that was just written.
        let task: Task =
            sqlx::query_as("INSERT INTO tasks (title, project_id) VALUES (?, ?) RETURNING *")
                .bind(title)
                .bind(project_id)
                .fetch_one(pool)
                .await?;

        // Tell subscribers. send() errors when nobody is listening; ignore that.
        let events = ctx.data::<broadcast::Sender<Task>>()?;
        let _ = events.send(task.clone());

        Ok(task)
    }

    // ---- Partial update ----
    #[graphql(guard = "LoggedIn")]
    async fn update_task(&self, ctx: &Context<'_>, id: ID, input: UpdateTaskInput) -> Result<Task> {
        let pool = ctx.data::<SqlitePool>()?;
        let id: i64 = id.parse()?;

        // COALESCE(?, column): use the new value, or keep the old one when it is NULL.
        let task = sqlx::query_as(
            "UPDATE tasks
             SET title = COALESCE(?, title), done = COALESCE(?, done)
             WHERE id = ?
             RETURNING *",
        )
        .bind(input.title)
        .bind(input.done)
        .bind(id)
        .fetch_optional(pool)
        .await?;

        // No row came back = the id did not exist.
        task.ok_or_else(|| Error::new(format!("Task {id} not found")))
    }

    // ---- Delete ----
    #[graphql(guard = "LoggedIn")]
    async fn delete_task(&self, ctx: &Context<'_>, id: ID) -> Result<bool> {
        let pool = ctx.data::<SqlitePool>()?;
        let id: i64 = id.parse()?;

        let result = sqlx::query("DELETE FROM tasks WHERE id = ?")
            .bind(id)
            .execute(pool)
            .await?;

        if result.rows_affected() == 0 {
            return Err(Error::new(format!("Task {id} not found")));
        }
        Ok(true)
    }

    // ---- Delete a parent that may still have children ----
    #[graphql(guard = "LoggedIn")]
    async fn delete_project(&self, ctx: &Context<'_>, id: ID) -> Result<bool> {
        let pool = ctx.data::<SqlitePool>()?;
        let id: i64 = id.parse()?;

        let task_count: i64 = sqlx::query_scalar("SELECT COUNT(*) FROM tasks WHERE project_id = ?")
            .bind(id)
            .fetch_one(pool)
            .await?;
        if task_count > 0 {
            return Err(Error::new(format!("Project {id} still has {task_count} tasks")));
        }

        let result = sqlx::query("DELETE FROM projects WHERE id = ?")
            .bind(id)
            .execute(pool)
            .await?;
        if result.rows_affected() == 0 {
            return Err(Error::new(format!("Project {id} not found")));
        }
        Ok(true)
    }

    // ---- Register and login (no guard: these are how you get a token) ----
    async fn register(&self, ctx: &Context<'_>, input: CredentialsInput) -> Result<AuthPayload> {
        let pool = ctx.data::<SqlitePool>()?;
        let username = input.username.trim();
        if username.is_empty() || input.password.len() < 8 {
            return Err(Error::new("Username required, password at least 8 characters"));
        }

        let password_hash = auth::hash_password(&input.password)?;
        let user: User = sqlx::query_as(
            "INSERT INTO users (username, password_hash) VALUES (?, ?) RETURNING *",
        )
        .bind(username)
        .bind(password_hash)
        .fetch_one(pool)
        .await
        // The UNIQUE constraint rejects a duplicate; turn that into a readable error.
        .map_err(|_| Error::new("Username is already taken"))?;

        let token = auth::make_token(user.id, ctx.data::<JwtSecret>()?)?;
        Ok(AuthPayload { token, user })
    }

    async fn login(&self, ctx: &Context<'_>, input: CredentialsInput) -> Result<AuthPayload> {
        let pool = ctx.data::<SqlitePool>()?;
        let user: Option<User> = sqlx::query_as("SELECT * FROM users WHERE username = ?")
            .bind(input.username.trim())
            .fetch_optional(pool)
            .await?;

        // One message for both failures, so nobody can probe which usernames exist.
        let user = user
            .filter(|u| auth::verify_password(&input.password, &u.password_hash))
            .ok_or_else(|| Error::new("Invalid username or password"))?;

        let token = auth::make_token(user.id, ctx.data::<JwtSecret>()?)?;
        Ok(AuthPayload { token, user })
    }
}

Authentication

src/auth.rs · Milestone 8

Four small pieces: hashing passwords, creating tokens, reading a token from a request, and a guard that blocks anonymous requests. The handler in main.rs and register/login in mutation.rs are what call them.

use std::time::{Duration, SystemTime, UNIX_EPOCH};

use argon2::Argon2;
use argon2::password_hash::{PasswordHasher, PasswordVerifier, phc::PasswordHash};
use async_graphql::{Context, Guard, Result};
use axum::http::HeaderMap;
use jsonwebtoken::{DecodingKey, EncodingKey, Header, Validation};
use serde::{Deserialize, Serialize};

// ---- Passwords ----

pub fn hash_password(password: &str) -> Result<String> {
    // A random salt is generated for you and stored inside the hash string.
    let hash = Argon2::default().hash_password(password.as_bytes())?;
    Ok(hash.to_string()) // this string is what you store
}

pub fn verify_password(password: &str, stored_hash: &str) -> bool {
    match PasswordHash::new(stored_hash) {
        Ok(hash) => Argon2::default()
            .verify_password(password.as_bytes(), &hash)
            .is_ok(),
        Err(_) => false,
    }
}

// ---- Tokens ----

// The secret used to sign tokens. A newtype so it can live in schema data.
#[derive(Clone)]
pub struct JwtSecret(pub String);

// What is stored inside the token.
#[derive(Serialize, Deserialize)]
struct Claims {
    sub: i64,   // subject: the user id
    exp: usize, // expiry, as seconds since 1970
}

pub fn make_token(user_id: i64, secret: &JwtSecret) -> Result<String> {
    let expires = SystemTime::now() + Duration::from_secs(24 * 60 * 60);
    let claims = Claims {
        sub: user_id,
        exp: expires.duration_since(UNIX_EPOCH)?.as_secs() as usize,
    };
    let key = EncodingKey::from_secret(secret.0.as_bytes());
    Ok(jsonwebtoken::encode(&Header::default(), &claims, &key)?)
}

// ---- The current user ----

// Attached to a request when it carries a valid token.
pub struct CurrentUser {
    pub id: i64,
}

// Reads "Authorization: Bearer <token>". None = anonymous.
pub fn user_from_headers(headers: &HeaderMap, secret: &JwtSecret) -> Option<CurrentUser> {
    let value = headers.get("Authorization")?.to_str().ok()?;
    let token = value.strip_prefix("Bearer ")?;
    let key = DecodingKey::from_secret(secret.0.as_bytes());
    // decode checks the signature and the expiry.
    let data = jsonwebtoken::decode::<Claims>(token, &key, &Validation::default()).ok()?;
    Some(CurrentUser { id: data.claims.sub })
}

// ---- Guard ----

// A reusable check that runs before a resolver.
pub struct LoggedIn;

impl Guard for LoggedIn {
    async fn check(&self, ctx: &Context<'_>) -> Result<()> {
        match ctx.data_opt::<CurrentUser>() {
            Some(_) => Ok(()),
            None => Err("Not authenticated".into()),
        }
    }
}

Subscriptions

src/schema/subscription.rs · Milestone 9

The receiving end of the broadcast channel. The sending end is the events.send(...) call in create_task.

use async_graphql::{Context, Result, Subscription};
use tokio::sync::broadcast;
use tokio_stream::wrappers::BroadcastStream;
use tokio_stream::{Stream, StreamExt};

use crate::models::Task;

pub struct Subscription;

#[Subscription]
impl Subscription {
    // Returns a stream: one Task is pushed to the client per event.
    // `+ use<>` says the stream does not borrow from `ctx`, so it can outlive this call.
    async fn task_added(&self, ctx: &Context<'_>) -> Result<impl Stream<Item = Task> + use<>> {
        let events = ctx.data::<broadcast::Sender<Task>>()?;
        // subscribe() gives this client its own receiver.
        let stream = BroadcastStream::new(events.subscribe());
        // Items are Results (a slow client can miss events); keep the Ok ones.
        Ok(stream.filter_map(|event| event.ok()))
    }
}

Tests run queries straight against the schema, with no HTTP server. serde_json is a dev-dependency used to compare results.

use std::time::Duration;

use async_graphql::Request;
use serde_json::json;
use sqlx::sqlite::SqlitePoolOptions;
use tokio_stream::StreamExt;

use crate::auth::{CurrentUser, JwtSecret};
use crate::schema::{AppSchema, build_schema};

// A fresh database per test. Each connection to sqlite::memory: is its own
// database, so the pool must be limited to one connection.
async fn test_schema() -> AppSchema {
    let pool = SqlitePoolOptions::new()
        .max_connections(1)
        .connect("sqlite::memory:")
        .await
        .unwrap();
    sqlx::migrate!().run(&pool).await.unwrap();
    build_schema(pool, JwtSecret("test-secret".into()))
}

// A request that looks logged in: attach CurrentUser, as the handler does.
fn as_user(query: &str) -> Request {
    Request::new(query).data(CurrentUser { id: 1 })
}

#[tokio::test]
async fn query_returns_data() {
    let schema = test_schema().await;
    let response = schema.execute("{ task(id: 1) { title project { name } } }").await;

    assert!(response.errors.is_empty());
    assert_eq!(
        response.data.into_json().unwrap(),
        json!({ "task": { "title": "Buy seeds", "project": { "name": "Garden" } } })
    );
}

#[tokio::test]
async fn pagination_reports_next_page() {
    let schema = test_schema().await;
    let response = schema
        .execute("{ tasks(limit: 2, offset: 0) { items { id } totalCount hasNextPage } }")
        .await;

    assert_eq!(
        response.data.into_json().unwrap(),
        json!({ "tasks": {
            "items": [{ "id": "1" }, { "id": "2" }],
            "totalCount": 3,
            "hasNextPage": true
        } })
    );
}

#[tokio::test]
async fn mutation_needs_login() {
    let schema = test_schema().await;
    let query = r#"mutation { createTask(input: { title: "Water", projectId: 1 }) { title } }"#;

    let anonymous = schema.execute(query).await;
    assert_eq!(anonymous.errors[0].message, "Not authenticated");

    let logged_in = schema.execute(as_user(query)).await;
    assert!(logged_in.errors.is_empty());
}

#[tokio::test]
async fn unknown_id_is_an_error() {
    let schema = test_schema().await;
    let response = schema.execute(as_user("mutation { deleteTask(id: 99) }")).await;
    assert_eq!(response.errors[0].message, "Task 99 not found");
}

#[tokio::test]
async fn subscription_receives_new_task() {
    let schema = test_schema().await;
    let mut stream = schema.execute_stream("subscription { taskAdded { title } }");

    // Poll once so the subscription is registered before the mutation runs.
    // Nothing has been sent yet, so this is expected to time out.
    let nothing_yet = tokio::time::timeout(Duration::from_millis(50), stream.next()).await;
    assert!(nothing_yet.is_err());

    schema
        .execute(as_user(
            r#"mutation { createTask(input: { title: "Water", projectId: 1 }) { id } }"#,
        ))
        .await;

    let event = stream.next().await.unwrap();
    assert_eq!(
        event.data.into_json().unwrap(),
        json!({ "taskAdded": { "title": "Water" } })
    );
}

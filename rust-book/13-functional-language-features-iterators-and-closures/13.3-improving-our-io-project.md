# 13.3 - Improving Our I/O Project

## High-Level Overview

This chapter applies the iterator concepts from the previous sections to refactor the `minigrep` I/O project from Chapter 12. The goal is to eliminate unnecessary `clone` calls and simplify logic using iterator adapters, resulting in cleaner, more idiomatic Rust code — without sacrificing performance.

---

## Key Refactoring: Removing `clone` with Iterators

### The Problem in the Original Code

The original `Config::build` accepted a `&[String]` slice and had to **clone** values because it only had references — it needed owned `String` values for the struct fields:

```rust
// Original: cloning to get owned values from references
impl Config {
    pub fn build(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let file_path = args[2].clone();
        let ignore_case = env::var("IGNORE_CASE").is_ok();

        Ok(Config { query, file_path, ignore_case })
    }
}
```

### The Fix: Pass the Iterator Directly

Instead of collecting `env::args()` into a `Vec<String>` first and then passing a reference, pass the iterator itself so ownership can be transferred:

**Before (`main.rs`):**
```rust
let args: Vec<String> = env::args().collect();
let config = Config::build(&args).unwrap_or_else(|err| { ... });
```

**After (`main.rs`):**
```rust
let config = Config::build(env::args()).unwrap_or_else(|err| { ... });
```

---

## Updated `Config::build` Signature

The function signature changes to accept `impl Iterator<Item = String>`, which means it works with any iterator that yields owned `String` values:

```rust
pub fn build(
    mut args: impl Iterator<Item = String>,
) -> Result<Config, &'static str> {
    args.next(); // skip the program name (first argument)

    let query = match args.next() {
        Some(arg) => arg,
        None => return Err("Didn't get a query string"),
    };

    let file_path = match args.next() {
        Some(arg) => arg,
        None => return Err("Didn't get a file path"),
    };

    let ignore_case = env::var("IGNORE_CASE").is_ok();

    Ok(Config { query, file_path, ignore_case })
}
```

**Benefits:**
- No more `.clone()` calls — ownership is transferred directly from the iterator.
- Clearer error messages using `match` on `Option` from `next()` instead of index bounds checking.
- More expressive: reads as "get the next argument or return an error."

## Simplifying the `search` Function with Iterator Adapters

### Original: Imperative Style with Mutable State

```rust
pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let mut results = Vec::new();

    for line in contents.lines() {
        if line.contains(query) {
            results.push(line);
        }
    }

    results
}
```

### Refactored: Functional Style with Iterator Adapters

```rust
pub fn search<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    contents
        .lines()
        .filter(|line| line.contains(query))
        .collect()
}
```

**Why this is better:**
- Eliminates the mutable `results` vector — no intermediate state to reason about.
- Expresses intent directly: "filter lines that contain the query, then collect."
- Easier to extend: add more adapters (e.g., `.map(...)`) without restructuring the loop.

---

## Important Concepts Reinforced

### `impl Trait` in Function Parameters

Using `impl Iterator<Item = String>` as a parameter type is idiomatic Rust for accepting any type that satisfies the trait bound. This is more flexible than requiring a concrete type like `Vec<String>`.

### Zero-Cost Abstractions

The iterator-based `search` function compiles to the same machine code as the hand-written loop. Rust's optimizer eliminates the abstraction overhead — you get expressiveness without a performance penalty.

### Functional vs Imperative Style

| Style       | Code Pattern                         | Tradeoff                              |
|-------------|--------------------------------------|---------------------------------------|
| Imperative  | `for` loop + mutable `Vec`           | Familiar, but more state to track     |
| Functional  | `.filter().collect()`                | Concise, no mutable state, composable |

Both are valid Rust; the functional style is often preferred when it clearly expresses intent.

---

## Summary

| Change                     | Before                        | After                              |
|----------------------------|-------------------------------|------------------------------------|
| Argument passing           | `&[String]` (slice reference) | `impl Iterator<Item = String>`     |
| Ownership of fields        | `.clone()` to copy values     | `next()` transfers ownership       |
| `search` function          | `for` loop + mutable `Vec`    | `.filter().collect()` pipeline     |
| Intermediate `Vec` in main | `env::args().collect()`       | Passed directly to `Config::build` |

The refactoring demonstrates a key Rust principle: **using ownership and iterators together eliminates unnecessary copying while making code more expressive.**

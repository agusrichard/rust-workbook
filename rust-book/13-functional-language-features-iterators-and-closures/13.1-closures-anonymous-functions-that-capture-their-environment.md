# 13.1 - Closures: Anonymous Functions that Capture Their Environment

## High-Level Overview

Rust closures are unnamed, anonymous functions that can be stored in variables or passed as arguments to other functions. What makes them distinct from regular functions is their ability to **capture values from the scope in which they are defined**. This chapter introduces closures, explains how they capture their environment, and describes the `Fn` trait family that governs their behavior.

---

## Key Concepts

### 1. Capturing the Environment

Closures can reference variables from their surrounding scope. Regular functions cannot do this — all inputs must be explicitly passed as parameters.

**Example: T-shirt giveaway scenario**

```rust
#[derive(Debug, PartialEq, Copy, Clone)]
enum ShirtColor { Red, Blue }

struct Inventory {
    shirts: Vec<ShirtColor>,
}

impl Inventory {
    fn giveaway(&self, user_preference: Option<ShirtColor>) -> ShirtColor {
        user_preference.unwrap_or_else(|| self.most_stocked())
    }

    fn most_stocked(&self) -> ShirtColor {
        // returns the most stocked color
    }
}
```

The closure `|| self.most_stocked()` captures an immutable reference to `self` from the enclosing scope — no parameters needed.

---

### 2. Type Inference and Annotation

Unlike functions, closures don't require explicit type annotations. The compiler infers parameter and return types from context.

```rust
// All of these are equivalent:
let add_one_v1 = |x: u32| -> u32 { x + 1 }; // fully annotated
let add_one_v2 = |x| { x + 1 };              // inferred
let add_one_v3 = |x| x + 1;                  // braces optional for single expression
```

**Important:** Once a closure's types are inferred from the first call, they are locked in. Calling the same closure with a different type causes a compile-time error.

```rust
let example = |x| x;
let s = example(String::from("hello")); // inferred as String
let n = example(5); // ERROR: expected String, found integer
```

---

### 3. Three Capture Modes

Closures capture environment values in one of three ways, automatically chosen by the compiler based on how they use the captured value:

#### a) Immutable Borrowing (`&T`)
Used when the closure only reads the captured value.

```rust
let list = vec![1, 2, 3];
let only_borrows = || println!("From closure: {list:?}");
only_borrows();
println!("After calling closure: {list:?}"); // list still accessible
```

#### b) Mutable Borrowing (`&mut T`)
Used when the closure modifies the captured value. Note: no other borrows can exist while the mutable borrow is held.

```rust
let mut list = vec![1, 2, 3];
let mut borrows_mutably = || list.push(7);
borrows_mutably();
println!("After calling closure: {list:?}");
```

#### c) Taking Ownership (`move`)
The `move` keyword forces the closure to take ownership of captured values. Most useful when passing closures to new threads, ensuring the data outlives the spawning scope.

```rust
use std::thread;

let list = vec![1, 2, 3];
thread::spawn(move || println!("From thread: {list:?}"))
    .join()
    .unwrap();
```

---

### 4. The `Fn` Trait Family

What a closure does with its captured values determines which of three traits it implements:

| Trait | Behavior | Called |
|-------|----------|--------|
| `FnOnce` | Moves captured values out of its body | At most once |
| `FnMut` | May mutate captured values, does not move them out | Multiple times |
| `Fn` | Neither moves nor mutates captured values | Multiple times |

Every closure implements at least `FnOnce`. Closures that don't move out captured values also implement `FnMut`. Closures that don't mutate captured values also implement `Fn`.

#### `FnOnce` — Used by `unwrap_or_else`
```rust
// unwrap_or_else only calls the closure at most once
user_preference.unwrap_or_else(|| self.most_stocked())
```

#### `FnMut` — Used by `sort_by_key`
`sort_by_key` calls the closure once per element, so it requires `FnMut`.

```rust
let mut list = vec![
    Rectangle { width: 10, height: 1 },
    Rectangle { width: 3, height: 5 },
];

let mut num_sort_operations = 0;
list.sort_by_key(|r| {
    num_sort_operations += 1; // mutates captured value — ok for FnMut
    r.width
});
```

**Counter-example** — the following fails because it tries to move a value out of the closure body on each call, which violates `FnMut`:

```rust
let mut sort_operations = vec![];
let value = String::from("closure called");

list.sort_by_key(|r| {
    sort_operations.push(value); // ERROR: moves `value`, can only happen once
    r.width
});
```

---

## Key Takeaways

- Closures **capture their environment**, which regular functions cannot.
- Type annotations are **optional** — the compiler infers them, but they are locked in after first use.
- The capture mode (borrow, mutable borrow, or move) is determined automatically; use `move` to force ownership transfer.
- The `Fn` traits (`FnOnce`, `FnMut`, `Fn`) describe what a closure does with captured values and determine where it can be used.
- Understanding closure traits is essential for writing flexible, higher-order functions that work correctly with Rust's ownership and borrow checker.

# 13.1 - Closures: Anonymous Functions that Capture Their Environment

## High-Level Overview

Rust closures are unnamed, anonymous functions that can be stored in variables or passed as arguments to other functions. What makes them distinct from regular functions is their ability to **capture values from the scope in which they are defined**. This chapter introduces closures, explains how they capture their environment, and describes the `Fn` trait family that governs their behavior.

---

## Key Concepts

### 1. Capturing the Environment

Closures can reference variables from their surrounding scope. Regular functions cannot do this — all inputs must be explicitly passed as parameters.

**Example: T-shirt giveaway scenario (Listing 13-1 & 13-2)**

```rust
#[derive(Debug, PartialEq, Copy, Clone)]
enum ShirtColor {
    Red,
    Blue,
}

struct Inventory {
    shirts: Vec<ShirtColor>,
}

impl Inventory {
    fn giveaway(&self, user_preference: Option<ShirtColor>) -> ShirtColor {
        user_preference.unwrap_or_else(|| self.most_stocked())
    }

    fn most_stocked(&self) -> ShirtColor {
        let mut num_red = 0;
        let mut num_blue = 0;

        for color in &self.shirts {
            match color {
                ShirtColor::Red => num_red += 1,
                ShirtColor::Blue => num_blue += 1,
            }
        }
        if num_red > num_blue {
            ShirtColor::Red
        } else {
            ShirtColor::Blue
        }
    }
}

fn main() {
    let store = Inventory {
        shirts: vec![ShirtColor::Blue, ShirtColor::Red, ShirtColor::Blue],
    };

    let user_pref1 = Some(ShirtColor::Red);
    let giveaway1 = store.giveaway(user_pref1);
    println!(
        "The user with preference {:?} gets {:?}",
        user_pref1, giveaway1
    );

    let user_pref2 = None;
    let giveaway2 = store.giveaway(user_pref2);
    println!(
        "The user with preference {:?} gets {:?}",
        user_pref2, giveaway2
    );
}
```

The closure `|| self.most_stocked()` captures an immutable reference to `self` from the enclosing scope — no parameters needed. `unwrap_or_else` accepts any closure that implements `FnOnce() -> T`.

### 2. Type Inference and Annotation

Unlike functions, closures don't require explicit type annotations. The compiler infers parameter and return types from context. Annotations can be added for clarity.

**Listing 13-3 — syntax comparison:**

```rust
fn  add_one_v1   (x: u32) -> u32 { x + 1 }   // regular function
let add_one_v2 = |x: u32| -> u32 { x + 1 };  // fully annotated closure
let add_one_v3 = |x|             { x + 1 };  // inferred types, with braces
let add_one_v4 = |x|               x + 1  ;  // inferred types, no braces
```

**Important:** Once a closure's types are inferred from the first call, they are **locked in**. Calling the same closure with a different type causes a compile-time error.

```rust
let example_closure = |x| x;

let s = example_closure(String::from("hello")); // type inferred as String
let n = example_closure(5); // ERROR: expected String, found integer
```

### 3. Three Capture Modes

Closures capture environment values in one of three ways, automatically chosen by the compiler based on how they use the captured value:

#### a) Immutable Borrowing (`&T`) — Listing 13-4

Used when the closure only reads the captured value.

```rust
fn main() {
    let list = vec![1, 2, 3];
    println!("Before defining closure: {list:?}");

    let only_borrows = || println!("From closure: {list:?}");

    println!("Before calling closure: {list:?}");
    only_borrows();
    println!("After calling closure: {list:?}");
}
```

`list` remains accessible everywhere because only immutable borrows exist.

#### b) Mutable Borrowing (`&mut T`) — Listing 13-5

Used when the closure modifies the captured value. No other borrows can exist while the mutable borrow is held.

```rust
fn main() {
    let mut list = vec![1, 2, 3];
    println!("Before defining closure: {list:?}");

    let mut borrows_mutably = || list.push(7);

    borrows_mutably();
    println!("After calling closure: {list:?}");
}
```

> Note: You cannot use `list` between defining `borrows_mutably` and calling it, because the mutable borrow is active during that window.

#### c) Taking Ownership (`move`) — Listing 13-6

The `move` keyword forces the closure to take ownership of captured values. Most useful when passing closures to new threads, ensuring the data outlives the spawning scope.

```rust
use std::thread;

fn main() {
    let list = vec![1, 2, 3];
    println!("Before defining closure: {list:?}");

    thread::spawn(move || println!("From thread: {list:?}"))
        .join()
        .unwrap();
}
```

Rust can't tell how long the spawned thread will run, so it requires ownership — `move` makes this explicit.

### 4. The `Fn` Trait Family

What a closure does with its captured values determines which of three traits it implements. These traits are **automatically** implemented by the compiler:

| Trait      | Behavior                                                      | Called         |
|------------|---------------------------------------------------------------|----------------|
| `FnOnce`   | Moves captured values out of its body                         | At most once   |
| `FnMut`    | May mutate captured values but does not move them out         | Multiple times |
| `Fn`       | Neither moves nor mutates captured values (or captures none)  | Multiple times |

Every closure implements at least `FnOnce`. Closures that don't move out captured values also implement `FnMut`. Closures that don't mutate also implement `Fn`.

When specifying a closure as a function parameter, using `Fn` is the most restrictive (accepts fewer closures), and `FnOnce` is the most permissive.

#### `FnOnce` — Listing 13-7: `unwrap_or_else` signature

```rust
impl<T> Option<T> {
    pub fn unwrap_or_else<F>(self, f: F) -> T
    where
        F: FnOnce() -> T
    {
        match self {
            Some(x) => x,
            None => f(),
        }
    }
}
```

`FnOnce() -> T` means: the closure takes no arguments, returns `T`, and may be called at most once. This is the least restrictive bound, accepting all closures.

#### `FnMut` — Listing 13-8: `sort_by_key` with a simple key

`sort_by_key` calls the closure once per element during sorting, so it requires `FnMut`.

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let mut list = [
        Rectangle { width: 10, height: 1 },
        Rectangle { width: 3, height: 5 },
        Rectangle { width: 7, height: 12 },
    ];

    list.sort_by_key(|r| r.width);
    println!("{list:#?}");
}
```

#### `FnMut` — Listing 13-9: Counting sort operations (valid)

```rust
fn main() {
    let mut list = [
        Rectangle { width: 10, height: 1 },
        Rectangle { width: 3, height: 5 },
        Rectangle { width: 7, height: 12 },
    ];

    let mut num_sort_operations = 0;
    list.sort_by_key(|r| {
        num_sort_operations += 1; // mutates captured value — valid for FnMut
        r.width
    });
    println!("{list:#?}, sorted in {num_sort_operations} operations");
}
```

#### Invalid: Trying to move a value out inside `sort_by_key` — Listing 13-10

This fails because `value` is moved out of the closure on the **first** call, leaving nothing for subsequent calls. This violates the `FnMut` requirement.

```rust
fn main() {
    let mut list = [
        Rectangle { width: 10, height: 1 },
        Rectangle { width: 3, height: 5 },
        Rectangle { width: 7, height: 12 },
    ];

    let mut sort_operations = vec![];
    let value = String::from("closure called");

    list.sort_by_key(|r| {
        sort_operations.push(value); // ERROR: moves `value`, can only happen once
        r.width
    });
    println!("{list:#?}");
}
```

---

## Key Takeaways

- Closures **capture their environment**, which regular functions cannot.
- Type annotations are **optional** — the compiler infers them, but they are locked in after the first use.
- The capture mode (immutable borrow, mutable borrow, or ownership via `move`) is chosen automatically by the compiler based on how the closure uses the value.
- Use `move` to force ownership transfer — essential for passing closures across thread boundaries.
- The `Fn` traits (`FnOnce`, `FnMut`, `Fn`) describe what a closure does with captured values and determine where it can be used as a function parameter.
- `FnOnce` is the most permissive bound; `Fn` is the most restrictive.
- Understanding closure traits is essential for writing flexible, higher-order functions that work correctly with Rust's ownership and borrow checker.

# 13.2 - Processing a Series of Items with Iterators

## High-Level Overview

Iterators are a core feature in Rust that allow you to process sequences of items one at a time. Rust's iterator pattern is **lazy**: iterators do nothing until they are consumed. This design enables efficient, expressive code without unnecessary computation.

---

## Key Concepts

### 1. The `Iterator` Trait

All iterators in Rust implement the `Iterator` trait from the standard library. The only required method is `next`, which returns items one at a time wrapped in `Option`:

```rust
pub trait Iterator {
    type Item;

    fn next(&mut self) -> Option<Self::Item>;

    // many default methods omitted...
}
```

- Returns `Some(item)` for each item in the sequence.
- Returns `None` when the iterator is exhausted.

### 2. Creating an Iterator

You can create an iterator from a vector using `.iter()`:

```rust
let v1 = vec![1, 2, 3];
let v1_iter = v1.iter();
```

The iterator itself does nothing until you use it — this is the **lazy evaluation** principle.

You can consume it in a `for` loop (which calls `next` implicitly):

```rust
for val in v1_iter {
    println!("Got: {val}");
}
```

### 3. Calling `next` Directly

You can call `next` manually, but the iterator must be `mut` since calling `next` changes internal state:

```rust
let mut v1_iter = v1.iter();

assert_eq!(v1_iter.next(), Some(&1));
assert_eq!(v1_iter.next(), Some(&2));
assert_eq!(v1_iter.next(), Some(&3));
assert_eq!(v1_iter.next(), None);
```

> Note: Values returned by `.iter()` are **immutable references** (`&T`).

---

## Three Types of Iterators

| Method       | Returns             | Ownership        |
|--------------|---------------------|------------------|
| `iter()`     | `&T`                | Borrows immutably |
| `iter_mut()` | `&mut T`            | Borrows mutably  |
| `into_iter()`| `T` (owned values)  | Takes ownership  |

---

## Consuming Adapters

Methods that call `next` internally and use up the iterator are called **consuming adapters**. Once consumed, the iterator cannot be used again.

### Example: `sum`

```rust
let v1 = vec![1, 2, 3];
let v1_iter = v1.iter();
let total: i32 = v1_iter.sum();

assert_eq!(total, 6);
// v1_iter is no longer usable here
```

---

## Iterator Adapters

Methods that transform an iterator into a different iterator are called **iterator adapters**. They are lazy — they don't do anything until consumed.

### Example: `map`

```rust
let v1: Vec<i32> = vec![1, 2, 3];
let v2: Vec<_> = v1.iter().map(|x| x + 1).collect();

assert_eq!(v2, vec![2, 3, 4]);
```

- `map` takes a closure and applies it to each element.
- `.collect()` is the consuming adapter that forces the lazy chain to execute and collects results into a `Vec`.

### Example: `filter` with Closures Capturing Environment

```rust
#[derive(PartialEq, Debug)]
struct Shoe {
    size: u32,
    style: String,
}

fn shoes_in_size(shoes: Vec<Shoe>, shoe_size: u32) -> Vec<Shoe> {
    shoes.into_iter().filter(|s| s.size == shoe_size).collect()
}
```

- `into_iter()` takes ownership of the vector.
- `filter` uses a closure that **captures** `shoe_size` from the enclosing scope.
- `.collect()` gathers the filtered items into a new `Vec<Shoe>`.

---

## Important Points

- **Lazy by default**: Iterator adapters like `map` and `filter` do nothing until a consuming adapter (like `collect` or `sum`) is called. Forgetting this results in a compiler warning about unused iterators.
- **Zero-cost abstraction**: Rust iterators compile down to the same machine code as equivalent hand-written loops — no runtime overhead.
- **Chaining**: Multiple adapter methods can be chained together for expressive, readable transformations.

```rust
let result: Vec<i32> = vec![1, 2, 3, 4, 5]
    .iter()
    .filter(|&&x| x % 2 == 0)
    .map(|&x| x * 10)
    .collect();

assert_eq!(result, vec![20, 40]);
```

---

## Summary

| Concept              | Description                                                  |
|----------------------|--------------------------------------------------------------|
| `Iterator` trait     | Defines `next` method; returns `Option<Self::Item>`          |
| Lazy evaluation      | Iterators do nothing until consumed                          |
| Consuming adapters   | Call `next` and exhaust the iterator (e.g., `sum`, `collect`)|
| Iterator adapters    | Transform iterators lazily (e.g., `map`, `filter`)           |
| Closure capture      | Iterator adapters can capture variables from their environment|
| Zero-cost abstraction| No runtime overhead compared to manual loops                 |

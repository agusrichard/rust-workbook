# Generic Data Types

## High-Level Overview

This section explains how to use generic type parameters in Rust to write flexible, reusable code that works with multiple data types while maintaining type safety and performance. Generics eliminate code duplication by allowing developers to define functions, structs, enums, and methods that operate on abstract type placeholders.

## Key Points

### Syntax and Declaration

Generic types use angle bracket notation (`<T>`) placed after function names or struct identifiers. Type parameter names conventionally use single uppercase letters, with `T` (short for "type") as the standard choice.

### Generic Functions

Two nearly identical functions (`largest_i32` and `largest_char`) can be merged into a single generic function:

```rust
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}
```

> Note: Using `>` on a generic `T` requires declaring that `T` implements the `PartialOrd` trait — Rust enforces explicit constraints rather than implicit assumptions.

### Generic Structs

**Single type parameter** — both fields must be the same type:

```rust
struct Point<T> {
    x: T,
    y: T,
}
```

**Multiple type parameters** — fields can have different types:

```rust
struct Point<T, U> {
    x: T,
    y: U,
}
```

### Generic Enums

Rust's standard library uses generics extensively:

```rust
enum Option<T> {
    Some(T),
    None,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

### Methods on Generic Types

Use `impl<T>` to implement methods for all instances of a generic type:

```rust
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}
```

**Specialized implementations** for specific concrete types only:

```rust
impl Point<f32> {
    fn distance_from_origin(&self) -> f32 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}
```

**Methods with their own generic parameters** distinct from the struct's:

```rust
impl<X1, Y1> Point<X1, Y1> {
    fn mixup<X2, Y2>(self, other: Point<X2, Y2>) -> Point<X1, Y2> {
        Point {
            x: self.x,
            y: other.y,
        }
    }
}
```

## Main Arguments

1. **Code Reusability** — single definitions accommodate multiple types, eliminating duplication.
2. **Type Safety** — constraints are enforced at compile time, preventing runtime type errors.
3. **Zero Runtime Cost** — monomorphization converts generic code into specialized concrete implementations at compile time.
4. **Design Clarity** — explicit trait requirements communicate intended capabilities rather than relying on implicit assumptions.

## Monomorphization: Zero-Cost Generics

Rust compiles generics via **monomorphization** — the compiler reads actual types used and generates specialized concrete code. For example:

```rust
// Written once as generic
let integer = Some(5);
let float = Some(5.0);

// Compiler expands to specialized enums:
enum Option_i32 {
    Some(i32),
    None,
}

enum Option_f64 {
    Some(f64),
    None,
}

fn main() {
    let integer = Option_i32::Some(5);
    let float = Option_f64::Some(5.0);
}
```

This means **we pay no runtime cost for using generics** — the abstraction exists only at the source level.

## Conclusions

Rust achieves flexibility and performance simultaneously through monomorphization. Generic code is as efficient as hand-written concrete code, while the type system ensures safety through explicit trait constraints. This makes generics the idiomatic Rust approach for any logic that should work across multiple types.

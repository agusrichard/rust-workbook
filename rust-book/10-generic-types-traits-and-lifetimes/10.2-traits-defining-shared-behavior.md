# 10.2 - Traits: Defining Shared Behavior

## High-Level Overview

A **trait** in Rust defines functionality that a type has and can share with other types. Traits allow you to define shared behavior in an abstract way — similar to interfaces in other languages. They enable writing generic code that works across multiple types as long as those types implement the required behavior. Traits are a cornerstone of Rust's type system and are used extensively throughout the standard library.

---

## Defining a Trait

Use the `trait` keyword followed by the trait name and method signatures. Method signatures end with `;` instead of a body — each implementing type provides its own behavior.

```rust
pub trait Summary {
    fn summarize(&self) -> String;
}
```

A trait can have multiple methods. All types that implement the trait must provide implementations for all methods without default implementations.

---

## Implementing a Trait on a Type

Use `impl TraitName for TypeName`:

```rust
pub struct NewsArticle {
    pub headline: String,
    pub location: String,
    pub author: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}, by {} ({})", self.headline, self.author, self.location)
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize(&self) -> String {
        format!("{}: {}", self.username, self.content)
    }
}
```

### The Orphan Rule

> "We can implement a trait on a type only if either the trait or the type, or both, are local to our crate."

This restriction (called the **orphan rule**) prevents conflicting implementations. You cannot implement an external trait on an external type — for example, you cannot implement `Display` on `Vec<T>` in your own crate.

---

## Default Implementations

Traits can provide default method implementations. Implementing types can override them or keep the defaults.

```rust
pub trait Summary {
    fn summarize(&self) -> String {
        String::from("(Read more...)")
    }
}

// Use the default implementation
impl Summary for NewsArticle {}
```

Default implementations can call other methods in the same trait — even those without defaults:

```rust
pub trait Summary {
    fn summarize_author(&self) -> String;

    fn summarize(&self) -> String {
        format!("(Read more from {}...)", self.summarize_author())
    }
}

impl Summary for SocialPost {
    fn summarize_author(&self) -> String {
        format!("@{}", self.username)
    }
}
```

> Note: You cannot call the default implementation from within an overriding implementation.

## Traits as Parameters

### `impl Trait` Syntax

Accept any type implementing a trait without naming the specific type:

```rust
pub fn notify(item: &impl Summary) {
    println!("Breaking news! {}", item.summarize());
}
```

### Trait Bound Syntax

The longer, equivalent form using generics:

```rust
pub fn notify<T: Summary>(item: &T) {
    println!("Breaking news! {}", item.summarize());
}
```

The trait bound form is more expressive when enforcing that two parameters are the **same** type:

```rust
// Both x and y must be the exact same type T that implements Summary
pub fn notify<T: Summary>(x: &T, y: &T) { ... }

// These can be different types, both implementing Summary
pub fn notify(x: &impl Summary, y: &impl Summary) { ... }
```

### Multiple Trait Bounds with `+`

Require a type to implement multiple traits:

```rust
pub fn notify(item: &(impl Summary + Display)) { ... }

// Or with trait bounds:
pub fn notify<T: Summary + Display>(item: &T) { ... }
```

### `where` Clauses for Cleaner Signatures

When there are many trait bounds, use `where` for readability:

```rust
// Hard to read
fn some_function<T: Display + Clone, U: Clone + Debug>(t: &T, u: &U) -> i32 { ... }

// Cleaner with where
fn some_function<T, U>(t: &T, u: &U) -> i32
where
    T: Display + Clone,
    U: Clone + Debug,
{
    // implementation
}
```

## Returning Types That Implement Traits

Use `impl Trait` as a return type to return a type implementing a trait without naming it:

```rust
fn returns_summarizable() -> impl Summary {
    SocialPost {
        username: String::from("horse_ebooks"),
        content: String::from("of course as you probably already know, people"),
        reply: false,
        repost: false,
    }
}
```

**Important limitation**: `impl Trait` in return position only works when returning a **single concrete type**. Returning different types conditionally requires trait objects (covered in Chapter 18).

```rust
// This does NOT compile — two different return types
fn returns_summarizable(switch: bool) -> impl Summary {
    if switch {
        NewsArticle { ... }
    } else {
        SocialPost { ... }  // ERROR
    }
}
```

---

## Using Trait Bounds to Conditionally Implement Methods

Implement methods on a generic type only when the type parameter satisfies certain trait bounds:

```rust
use std::fmt::Display;

struct Pair<T> {
    first: T,
    second: T,
}

impl<T> Pair<T> {
    fn new(first: T, second: T) -> Self {
        Self { first, second }
    }
}

impl<T: Display + PartialOrd> Pair<T> {
    fn cmp_display(&self) {
        if self.first >= self.second {
            println!("The largest member is first = {}", self.first);
        } else {
            println!("The largest member is second = {}", self.second);
        }
    }
}
```

---

## Blanket Implementations

Implement a trait for **any** type that satisfies a certain trait bound. The standard library uses this extensively:

```rust
// Implements ToString for every type that implements Display
impl<T: Display> ToString for T {
    // ...
}
```

This is why you can call `.to_string()` on any type that implements `Display`:

```rust
let s = 3.to_string();
```

---

## Summary

| Concept | Description |
|---|---|
| `trait` | Defines shared behavior via method signatures |
| `impl Trait for Type` | Implements a trait on a type |
| Orphan rule | Can only implement foreign traits on local types (or vice versa) |
| Default implementations | Traits can provide default method bodies |
| `impl Trait` (parameter) | Accepts any type implementing the trait |
| Trait bounds (`T: Trait`) | Equivalent to `impl Trait`, more expressive with generics |
| `+` syntax | Require multiple trait implementations |
| `where` clause | Cleaner syntax for complex trait bounds |
| `impl Trait` (return) | Return a type implementing a trait without naming it |
| Blanket implementations | Implement a trait for all types satisfying a bound |

Traits, combined with generics, enable Rust to catch type errors at **compile time** rather than runtime, providing flexibility without sacrificing performance.

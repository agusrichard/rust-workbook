# 10.0 - Generic Types, Traits, and Lifetimes

## High-Level Overview

Chapter 10 introduces three of Rust's most powerful tools for writing flexible, reusable, and correct code:

- **Generics** — abstract stand-ins for concrete types, eliminating code duplication
- **Traits** — define behavior generically and constrain which types are acceptable
- **Lifetimes** — a special kind of generic that gives the compiler information about reference relationships to ensure validity

Together, these features allow you to write code that works across many types without sacrificing compile-time safety or runtime performance.

---

## Key Concepts

### Generics

Generics are "abstract stand-ins for concrete types or other properties." They let you express the behavior of code without knowing the specific types at the time of writing — the compiler fills in the concrete types at compile time.

You've already used generics through standard library types:
- `Option<T>`
- `Vec<T>`
- `HashMap<K, V>`
- `Result<T, E>`

### Traits

Traits define shared behavior. When combined with generic type parameters, they act as **constraints** — specifying that a generic type must implement certain behavior to be used in a given context.

### Lifetimes

Lifetimes are a special category of generics. Rather than abstracting over types, they provide the compiler with information about how references relate to each other, ensuring that references remain valid for as long as they are used.

---

## The Motivation: Eliminating Duplication

The chapter teaches generics by analogy with a familiar technique: **extracting functions** to eliminate code duplication.

### Step 1 — Duplicate Code

Two separate code blocks, each finding the largest number in a different list:

```rust
fn main() {
    let number_list = vec![34, 50, 25, 100, 65];
    let mut largest = &number_list[0];
    for number in &number_list {
        if number > largest {
            largest = number;
        }
    }
    println!("The largest number is {largest}");

    let number_list = vec![102, 34, 6000, 89, 54, 2, 43, 8];
    let mut largest = &number_list[0];
    for number in &number_list {
        if number > largest {
            largest = number;
        }
    }
    println!("The largest number is {largest}");
}
```

### Step 2 — Extract a Function

Move the shared logic into a reusable function:

```rust
fn largest(list: &[i32]) -> &i32 {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}

fn main() {
    let number_list = vec![34, 50, 25, 100, 65];
    println!("The largest number is {}", largest(&number_list));

    let number_list = vec![102, 34, 6000, 89, 54, 2, 43, 8];
    println!("The largest number is {}", largest(&number_list));
}
```

### Step 3 — The Next Problem

If we also need a `largest` function for `char` slices, we'd have to duplicate the function again. The solution — using **generic type parameters** — is what the rest of the chapter covers.

---

## Summary

| Feature | Purpose |
|---|---|
| Generics | Eliminate duplication by abstracting over types |
| Traits | Define and constrain shared behavior |
| Lifetimes | Ensure reference validity by expressing relationships between references |

The same principle that motivates function extraction — **don't repeat yourself** — is exactly what motivates generics. The chapter extends this idea progressively from concrete functions to fully generic, trait-bounded, lifetime-annotated code.

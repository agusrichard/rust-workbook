# 10.1 - Generic Data Types

## High-Level Overview

Generic data types let you write flexible function and type definitions that work with multiple concrete types, eliminating code duplication while preserving full compile-time type safety. Rust supports generics in functions, structs, enums, and method implementations. Critically, generics have **zero runtime cost** — the compiler generates specialized versions for each concrete type used via a process called **monomorphization**.

---

## Generic Functions

Place type parameters in angle brackets `<T>` after the function name, before the parameter list:

```rust
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}
```

**Important:** The above won't compile as-is. The compiler can't assume that `T` supports the `>` comparison operator. You must add a **trait bound** to declare the required capability:

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}
```

This is the key difference from the concrete `largest` function from Chapter 10.0 — by adding `T: PartialOrd`, you tell the compiler that `T` must support comparison.

## Generic Structs

### Single Generic Parameter

All fields using `T` must be the **same** concrete type:

```rust
struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let integer = Point { x: 5, y: 10 };       // T = i32
    let float = Point { x: 1.0, y: 4.0 };      // T = f64
    // Point { x: 5, y: 4.0 }  // ERROR: mismatched types
}
```

### Multiple Generic Parameters

Use different type parameters to allow fields of different types:

```rust
struct Point<T, U> {
    x: T,
    y: U,
}

fn main() {
    let both_integer = Point { x: 5, y: 10 };
    let both_float = Point { x: 1.0, y: 4.0 };
    let integer_and_float = Point { x: 5, y: 4.0 };  // T = i32, U = f64
}
```

> Use multiple parameters sparingly — too many make code hard to read. Consider restructuring if you need many.

## Generic Enums

The standard library's most common generic enums:

```rust
enum Option<T> {
    Some(T),
    None,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

- `Option<T>` — represents an optional value (either `Some(T)` or `None`)
- `Result<T, E>` — represents success (`Ok(T)`) or failure (`Err(E)`)

These patterns are the template for recognizing generic enums in your own code.

## Generic Methods

### Methods on Generic Structs

Declare `<T>` after `impl` to use the generic in the method:

```rust
impl<T> Point<T> {
    fn x(&self) -> &T {
        &self.x
    }
}

fn main() {
    let p = Point { x: 5, y: 10 };
    println!("p.x = {}", p.x());
}
```

### Methods Only for Specific Concrete Types

Implement methods that only exist for a particular instantiation of the generic type:

```rust
impl Point<f32> {
    fn distance_from_origin(&self) -> f32 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}
```

`Point<i32>` will not have the `distance_from_origin` method — only `Point<f32>` will.

### Methods with Additional Generic Parameters

Methods can introduce their own generic parameters, separate from the struct's:

```rust
impl<X1, Y1> Point<X1, Y1> {
    fn mixup<X2, Y2>(self, other: Point<X2, Y2>) -> Point<X1, Y2> {
        Point {
            x: self.x,
            y: other.y,
        }
    }
}

fn main() {
    let p1 = Point { x: 5, y: 10.4 };
    let p2 = Point { x: "Hello", y: 'c' };
    let p3 = p1.mixup(p2);
    println!("p3.x = {}, p3.y = {}", p3.x, p3.y);
    // p3.x = 5, p3.y = c
}
```

Here `X1`, `Y1` belong to the struct, while `X2`, `Y2` are specific to the `mixup` method.

## Performance: Monomorphization

> "Using generic types won't make your program run any slower than it would with concrete types."

Rust uses **monomorphization** — the process of turning generic code into specific code by filling in the concrete types used at each call site. This happens at compile time.

### Example

You write:
```rust
let integer = Some(5);
let float = Some(5.0);
```

The compiler generates the equivalent of:
```rust
enum Option_i32 {
    Some(i32),
    None,
}

enum Option_f64 {
    Some(f64),
    None,
}
```

The compiled binary contains specialized implementations — identical in performance to hand-written concrete code. **Generics are a zero-cost abstraction in Rust.**

## Summary

| Context | Syntax | Notes |
|---|---|---|
| Function | `fn name<T>(...)` | Add trait bounds for operations on `T` |
| Struct (single) | `struct Name<T>` | All `T` fields must be the same type |
| Struct (multiple) | `struct Name<T, U>` | Fields can be different types |
| Enum | `enum Name<T>` | Used in `Option<T>`, `Result<T, E>` |
| Method (generic impl) | `impl<T> Name<T>` | Applies to all instantiations |
| Method (concrete impl) | `impl Name<f32>` | Only applies to that specific type |
| Method (own generics) | `fn method<X2, Y2>(...)` | Method's own type params, separate from struct's |
| Performance | Monomorphization | Zero runtime cost — compiler generates concrete versions |

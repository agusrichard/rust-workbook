### Defining an Enum

Enums (enumerations) allow you to define a type by enumerating its possible variants. While structs group related fields together, enums allow a value to be one of a set of distinct values.

#### 1. Basic Enum Definition

The text uses IP addresses as an example. An IP address can be either version four or version six, but not both. This is a perfect use case for an enum.

```rust
enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

```

#### 2. Storing Data Inside Enums

You can associate data directly with each enum variant. This is often more concise than using a struct.

**The Struct Approach (Less Concise):**
Here, the `kind` and the `address` data are separate fields.

```rust
enum IpAddrKind {
    V4,
    V6,
}

struct IpAddr {
    kind: IpAddrKind,
    address: String,
}

let home = IpAddr {
    kind: IpAddrKind::V4,
    address: String::from("127.0.0.1"),
};

let loopback = IpAddr {
    kind: IpAddrKind::V6,
    address: String::from("::1"),
};

```

**The Enum Approach (More Concise):**
Here, the data is attached directly to the variant.

```rust
enum IpAddr {
    V4(String),
    V6(String),
}

let home = IpAddr::V4(String::from("127.0.0.1"));
let loopback = IpAddr::V6(String::from("::1"));

```

Enums also allow different variants to hold **different types and amounts** of data. For example, V4 addresses can be stored as four `u8` integers, while V6 remains a `String`.

```rust
enum IpAddr {
    V4(u8, u8, u8, u8),
    V6(String),
}

let home = IpAddr::V4(127, 0, 0, 1);
let loopback = IpAddr::V6(String::from("::1"));

```

#### 3. A Wide Variety of Types

The `Message` enum demonstrates that variants can hold any kind of data, including strings, numeric types, or even named fields (like a struct).

```rust
enum Message {
    Quit,                       // No data associated
    Move { x: i32, y: i32 },    // Named fields (like a struct)
    Write(String),              // A single String
    ChangeColor(i32, i32, i32), // Three i32 values
}

```

#### 4. Defining Methods on Enums

Just like structs, you can define methods on enums using an `impl` block.

```rust
impl Message {
    fn call(&self) {
        // method body would be defined here
    }
}

let m = Message::Write(String::from("hello"));
m.call();

```

#### 5. The `Option` Enum and Null Safety

Rust does not have a `null` feature. Instead, it uses the `Option<T>` enum to encode the concept of a value being present (`Some`) or absent (`None`). This prevents errors caused by assuming a value is not null when it actually is.

**Standard Library Definition:**

```rust
enum Option<T> {
    None,
    Some(T),
}

```

**Usage Examples:**
The `<T>` syntax allows `Option` to hold any type of data.

```rust
let some_number = Some(5);
let some_char = Some('e');

// For None, we must explicitly tell Rust the type, as it cannot infer it.
let absent_number: Option<i32> = None;

```

**Why it is safer:**
You cannot simply add an `Option<T>` to a valid value (like `i8`) without handling the `None` case first. The compiler enforces safety by refusing to compile the following code:

```rust
let x: i8 = 5;
let y: Option<i8> = Some(5);

let sum = x + y; // This causes a compile-time error!

```

To use the value inside `y`, you must convert the `Option<T>` to a `T` (handling the `None` case), ensuring you never accidentally use a null value.

# The `match` Control Flow Construct

Rust’s `match` operator is a powerful control flow construct that allows you to compare a value against a series of patterns and execute code based on which pattern "fits." It is comparable to a switch statement in other languages but is significantly more expressive and safe because the compiler enforces that all possible cases are handled.

#### 1. Basic `match` Syntax

The text compares `match` to a coin-sorting machine: a value slides down and falls into the first "bucket" (arm) that matches.

A `match` expression is made up of **arms**. Each arm consists of:

* A **pattern** (e.g., `Coin::Penny`).
* The `=>` operator.
* The **code** to run if the pattern matches.

```rust
enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}

```

If the code block is short, you can use a single line. For multiple lines, use curly braces `{}`.

#### 2. Patterns That Bind to Values

`match` arms can extract values from inside an enum variant. In the example below, the `Quarter` variant holds a `UsState`. When the code matches `Coin::Quarter(state)`, the variable `state` binds to that inner value, making it accessible in the code block.

```rust
#[derive(Debug)]
enum UsState {
    Alabama,
    Alaska,
    // --snip--
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter(UsState),
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => {
            println!("State quarter from {state:?}!");
            25
        }
    }
}

```

#### 3. Matching with `Option<T>`

`match` is frequently used to handle `Option<T>`, which replaces the concept of null in Rust. You can write functions that safely operate on values only if they exist (`Some`), while handling the empty case (`None`).

```rust
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        None => None,
        Some(i) => Some(i + 1),
    }
}

let five = Some(5);
let six = plus_one(five);
let none = plus_one(None);

```

#### 4. Matches Are Exhaustive

Rust enforces exhaustiveness: **you must handle every possible case**. If you forget to handle a specific variant (like `None` in an `Option`), the code will not compile. This protects you from "billion-dollar mistakes" (null pointer errors).

```rust
// This code will NOT compile because it is missing the `None` arm.
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        Some(i) => Some(i + 1),
    }
}

```

#### 5. Catch-All Patterns and the `_` Placeholder

If you want to handle specific values and have a default action for everything else, you can use a catch-all pattern.

* **Variable catch-all (`other`):** Binds the value so you can use it.
* **Underscore catch-all (`_`):** Matches any value but **ignores** it (does not bind). This is useful when you don't need the value.

```rust
let dice_roll = 9;
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    other => move_player(other), // Catch-all that USES the value
}

match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => reroll(), // Catch-all that IGNORES the value
}

match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => (), // Do nothing (Unit value)
}

```

#### 6. Ownership and Match

When matching on an enum that contains non-copyable data (like `String`), the match can move the data out of the enum.

* **Move:** If you match `Some(s)`, the string `s` is moved out of the option, and the original option cannot be used afterward.
* **Borrow:** To check the value without moving it, you should match on a reference `match &opt`.

```rust
let opt: Option<String> = Some(String::from("Hello world"));

// Matching on a reference (&opt) prevents moving the inner String
match &opt {
    Some(s) => println!("Some: {}", s),
    None => println!("None!"),
};

println!("{:?}", opt); // This is valid because opt was borrowed, not moved

```

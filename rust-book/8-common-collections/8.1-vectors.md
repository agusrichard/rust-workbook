# Storing Lists of Values with Vectors

## High-Level Overview
This chapter introduces the `Vec<T>` type in Rust, commonly known as a vector. Vectors are collections that allow you to store multiple values of the same type sequentially in a single contiguous block of memory. They are extremely useful when you have a list of items, such as the lines of text in a file or the prices of items in a shopping cart.

## Key Points and Main Arguments

### 1. Creating a New Vector
- You can create an empty vector using the `Vec::new()` function. Because it's initially empty, you often need to provide a type annotation to tell Rust what kind of elements it will hold.
- A more common and convenient way to create a vector with initial values is using the `vec!` macro. Rust can infer the type of the vector based on the provided values.

```rust
// Creating an empty vector with type annotation
let v: Vec<i32> = Vec::new();

// Creating a vector with initial values using the vec! macro
let v = vec![1, 2, 3];
```

### 2. Updating a Vector
- To add elements to a vector, the vector must be declared as mutable (`mut`). You can then use the `push` method to append elements to the end.

```rust
let mut v = Vec::new();
v.push(5);
v.push(6);
v.push(7);
v.push(8);
```

### 3. Reading Elements of Vectors
- There are two ways to reference a value stored in a vector: via indexing or using the `get` method.
- **Indexing (`&v[index]`)**: Returns a reference to the element. If you access an index outside the vector's bounds, the program will panic and crash.
- **The `get` Method (`v.get(index)`)**: Returns an `Option<&T>`. This is safer when you suspect an out-of-bounds access might happen, allowing you to handle the `None` case gracefully without crashing.

```rust
let v = vec![1, 2, 3, 4, 5];

// Using indexing
let third: &i32 = &v[2];
println!("The third element is {third}");

// Using the get method
let third: Option<&i32> = v.get(2);
match third {
    Some(third) => println!("The third element is {third}"),
    None => println!("There is no third element."),
}
```

- **Borrowing Rules**: You cannot have mutable and immutable references to a vector in the same scope. This is because adding elements to a vector might require reallocating memory, which would invalidate any existing references.

```rust
// This code will result in a compile-time error
let mut v = vec![1, 2, 3, 4, 5];
let first = &v[0]; // Immutable borrow
v.push(6);         // Mutable borrow, might reallocate
println!("The first element is: {first}"); // Immutable borrow used after potential invalidation
```

### 4. Iterating Over the Values in a Vector
- You can iterate through all elements of a vector using a `for` loop, either immutably or mutably.

```rust
// Immutable iteration
let v = vec![100, 32, 57];
for i in &v {
    println!("{i}");
}

// Mutable iteration
let mut v = vec![100, 32, 57];
for i in &mut v {
    *i += 50; // Dereference to modify the value
}
```

### 5. Using an Enum to Store Multiple Types
- Vectors can only store values of a single type. To circumvent this, you can define an `enum` whose variants hold different types. Since the variants are considered the same `enum` type, the vector can hold multiple distinct types safely.

```rust
enum SpreadsheetCell {
    Int(i32),
    Float(f64),
    Text(String),
}

let row = vec![
    SpreadsheetCell::Int(3),
    SpreadsheetCell::Text(String::from("blue")),
    SpreadsheetCell::Float(10.12),
];
```

## Significant Conclusions
- Vectors are powerful, resizable data structures in Rust used for contiguous memory storage of same-type values.
- Accessing elements safely is encouraged via `get()` to prevent panics on out-of-bounds indexing.
- Rust's strict borrowing rules ensure memory safety by preventing simultaneous mutable and immutable references, which is especially critical when memory reallocation might occur during a `push`.
- By using an `enum`, developers can effectively store multiple data types within a single vector while still maintaining compile-time type safety.
- Like any other struct, a vector and all of its elements are dropped and their memory is freed when the vector goes out of scope.

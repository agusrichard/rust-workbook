# Storing UTF-8 Encoded Text with Strings

## High-Level Overview
This chapter explores Rust's handling of text through the `String` type and string slices (`&str`). Because Rust strings are UTF-8 encoded by default and memory safety is strictly enforced, strings are often considered complex by newcomers. The chapter covers creating, updating, indexing, and iterating over strings, while highlighting why direct indexing is forbidden to prevent subtle bugs with multi-byte characters.

## Key Points and Main Arguments

### 1. What Is a String?
- Rust has one core string type: the string slice `str`, usually seen as a borrowed reference `&str` (like string literals).
- The `String` type, provided by the standard library, is a growable, mutable, owned, and UTF-8 encoded wrapper over a `Vec<u8>`.

### 2. Creating a New String
- You can create an empty string with `String::new()` or initialize it with data using `String::from` or the `to_string` method on literals.

```rust
let mut s = String::new(); // Empty string

let data = "initial contents";
let s1 = data.to_string(); // From variable

let s2 = "initial contents".to_string(); // Directly on literal
let s3 = String::from("initial contents"); // Using String::from
```

### 3. Updating a String
- Since `String` is growable like a vector, you can append data to it.
- **`push_str`**: Appends a string slice (`&str`).
- **`push`**: Appends a single character (`char`).
- **Concatenation (`+`)**: Joins strings but takes ownership of the first operand.
- **`format!` Macro**: Convenient for complex string formatting without taking ownership.

```rust
// Appending
let mut s = String::from("foo");
s.push_str("bar"); // "foobar"
s.push('!');       // "foobar!"

// Concatenation with +
let s1 = String::from("Hello, ");
let s2 = String::from("world!");
let s3 = s1 + &s2; // s1 is moved and no longer valid; s3 is "Hello, world!"

// Formatting
let s1 = String::from("tic");
let s2 = String::from("tac");
let s3 = String::from("toe");
let s = format!("{s1}-{s2}-{s3}"); // "tic-tac-toe" without moving ownership
```

### 4. Indexing into Strings
- **Direct indexing is not allowed** (e.g., `s[0]`). This is because UTF-8 encoding means characters (Unicode scalar values) can vary in byte size (1 to 4 bytes). Indexing by byte could return an invalid or incomplete character.

```rust
let s1 = String::from("hi");
// let h = s1[0]; // ERROR: String cannot be indexed by integer
```

### 5. String Slicing
- Instead of single-character indexing, you can create string slices using a range of bytes. However, you must be cautious to slice precisely on character boundaries, or the program will panic at runtime.

```rust
let hello = "Здравствуйте"; // Each character takes 2 bytes
let s = &hello[0..4];       // Contains "Зд"
```

### 6. Iterating Over Strings
- Rust requires explicit choice when iterating over string contents to handle its internal byte representation correctly.
- **`chars()`**: Iterates over individual Unicode scalar values (`char`).
- **`bytes()`**: Iterates over the raw underlying bytes (`u8`).

```rust
// Iterating over characters
for c in "Зд".chars() {
    println!("{c}"); // Prints 'З' then 'д'
}

// Iterating over bytes
for b in "Зд".bytes() {
    println!("{b}"); // Prints 208, 151, 208, 180
}
```

## Significant Conclusions
- Strings in Rust expose the complexity of text representation upfront. Because text involves bytes, scalar values, and grapheme clusters, treating a string as a simple array of characters is unsafe.
- Direct character indexing is deliberately disabled to enforce O(1) time complexity constraints and prevent bugs related to malformed multi-byte strings.
- Operations like concatenation via `+` consume ownership, while the `format!` macro offers a non-consuming alternative.
- Developers must use methods like `chars()` or `bytes()` or careful slicing to interact with string contents, choosing the abstraction level (scalar vs. byte) that matches their need.

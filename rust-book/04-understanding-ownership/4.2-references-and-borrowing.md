# References and Borrowing

Rust uses **references** to allow access to data without taking ownership. This prevents the inconvenience of moving ownership back and forth for every function call.

## References Are Non-Owning Pointers

A reference is a pointer that borrows data rather than owning it. Because it does not own the data, the data is not dropped when the reference goes out of scope.

**Example: Passing References**
Using `&` creates a reference.

```rust
fn main() {
    let m1 = String::from("Hello");
    let m2 = String::from("world");
    greet(&m1, &m2); // Pass references, not ownership
    let s = format!("{} {}", m1, m2); // m1 and m2 are still valid here!
}

fn greet(g1: &String, g2: &String) {
    println!("{} {}!", g1, g2);
} // g1 and g2 go out of scope, but the Strings are NOT dropped

```

## Dereferencing

References are pointers. To access the underlying data, you use the dereference operator `*`.

- `&x`: Creates a reference to `x`.
- `*r`: Accesses the value `r` points to.

Rust often inserts dereferences implicitly (e.g., when calling methods with `.`).

**Example: Explicit vs Implicit Dereference**

```rust
let x: Box<i32> = Box::new(-1);
let x_abs1 = i32::abs(*x); // Explicit dereference
let x_abs2 = x.abs();      // Implicit dereference via dot syntax

```

## Aliasing and Mutation

Pointers enable **aliasing** (accessing data via multiple variables).

- **Aliasing** is safe on its own.
- **Mutation** is safe on its own.
- **Aliasing + Mutation** is dangerous (causes data races, use-after-free, etc.).

Rust prevents simultaneous aliasing and mutation at compile time using permissions.

## Permissions (The Borrow Checker)

The compiler tracks three permissions for every variable:

- **Read (R)**: Can copy data.
- **Write (W)**: Can mutate data.
- **Own (O)**: Can move or drop data.

### Immutable References (`&T`)

Creating an immutable reference temporarily removes **Write** and **Own** permissions from the owner.

- **Owner**: Loses Write and Own. Keeps Read.
- **Reference**: Gains Read.

This allows _many_ readers, but _no_ writers.

**Example: Immutable Borrow**

```rust
let mut v = vec![1, 2, 3];
let num = &v[2]; // v borrows to num
// v.push(4);    // Error! v lacks Write permission while borrowed by num
println!("Third element is {}", *num);
// num dies here, v regains Write/Own permissions

```

### Mutable References (`&mut T`)

Creating a mutable reference temporarily removes **Read**, **Write**, and **Own** permissions from the owner.

- **Owner**: Loses ALL permissions.
- **Reference**: Gains Read and Write.

This ensures **exclusive access**. Only the mutable reference can access the data.

**Example: Mutable Borrow**

```rust
let mut v = vec![1, 2, 3];
let num = &mut v[2]; // Exclusive borrow
*num += 1;           // Safe mutation via num
// println!("{:?}", v); // Error! v cannot be read while mutably borrowed

```

## Summary of Rules

1. At any given time, you can have **either** one mutable reference **or** any number of immutable references.
2. References must always be valid.

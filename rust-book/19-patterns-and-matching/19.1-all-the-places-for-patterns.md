# 19.1 - All the Places Patterns Can Be Used

## Overview

Patterns are a special syntax in Rust for matching against the structure of types. They appear in many places throughout the language — often in spots you might not immediately recognize as pattern matching. This section covers the six primary locations where patterns are valid in Rust.

---

## 1. `match` Arms

The most explicit use of patterns. A `match` expression compares a value against a series of patterns and runs code for the first one that matches.

**Syntax:**
```rust
match VALUE {
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
}
```

**Key rules:**
- `match` expressions must be **exhaustive** — all possible values must be covered.
- The wildcard pattern `_` acts as a catch-all for any remaining cases.

**Example:**
```rust
match x {
    None => None,
    Some(i) => Some(i + 1),
}
```

---

## 2. `let` Statements

Every `let` statement uses a pattern — even simple ones. The variable name on the left is itself a pattern.

**Simple pattern (identifier):**
```rust
let x = 5;
// `x` is a pattern that matches anything and binds the value to `x`
```

**Destructuring a tuple:**
```rust
fn main() {
    let (x, y, z) = (1, 2, 3);
}
```

**Type mismatch — compile error:**
```rust
fn main() {
    let (x, y) = (1, 2, 3); // ERROR: pattern has 2 elements, value has 3
}
```

> The pattern on the left must structurally match the type on the right. If they don't align, the compiler raises a type error.

---

## 3. `if let` Conditional Expressions

`if let` is a concise alternative to `match` when you only care about one pattern. You can chain `else if`, `else if let`, and `else` branches freely.

```rust
fn main() {
    let favorite_color: Option<&str> = None;
    let is_tuesday = false;
    let age: Result<u8, _> = "34".parse();

    if let Some(color) = favorite_color {
        println!("Using your favorite color, {color}, as the background");
    } else if is_tuesday {
        println!("Tuesday is green day!");
    } else if let Ok(age) = age {
        if age > 30 {
            println!("Using purple as the background color");
        } else {
            println!("Using orange as the background color");
        }
    } else {
        println!("Using blue as the background color");
    }
}
```

**Important difference from `match`:**  
The compiler does **not** enforce exhaustiveness for `if let`. This gives flexibility but means missed cases won't be caught at compile time.

---

## 4. `while let` Conditional Loops

`while let` keeps looping as long as the pattern continues to match. It's commonly used with channels or iterators that signal completion via a `None` or `Err`.

```rust
fn main() {
    let (tx, rx) = std::sync::mpsc::channel();
    std::thread::spawn(move || {
        for val in [1, 2, 3] {
            tx.send(val).unwrap();
        }
    });

    while let Ok(value) = rx.recv() {
        println!("{value}");
    }
}
```

The loop continues while `rx.recv()` returns `Ok(value)`. When the sender disconnects, `recv()` returns `Err`, and the loop ends.

---

## 5. `for` Loops

In a `for` loop, the variable immediately following the `for` keyword is a pattern. This makes tuple destructuring during iteration natural and readable.

```rust
fn main() {
    let v = vec!['a', 'b', 'c'];

    for (index, value) in v.iter().enumerate() {
        println!("{value} is at index {index}");
    }
}
```

`enumerate()` returns `(usize, &T)` tuples. The pattern `(index, value)` destructures each tuple directly in the loop head.

---

## 6. Function Parameters

Function parameters are also patterns. You can destructure values directly in a function's signature.

**Simple case (identifier pattern):**
```rust
fn foo(x: i32) {
    // x is a pattern
}
```

**Destructuring a tuple reference in the parameter:**
```rust
fn print_coordinates(&(x, y): &(i32, i32)) {
    println!("Current location: ({x}, {y})");
}

fn main() {
    let point = (3, 5);
    print_coordinates(&point);
}
```

Closures support this exact same syntax as function parameters.

## Summary Diagram

```
Patterns appear in:
┌─────────────────────────────────────────────────────┐
│  match VALUE { PATTERN => expr, ... }               │  match arms
│  let PATTERN = expr;                                │  let statements
│  if let PATTERN = expr { ... }                      │  if let
│  while let PATTERN = expr { ... }                   │  while let
│  for PATTERN in iter { ... }                        │  for loops
│  fn foo(PATTERN: Type) { ... }                      │  fn parameters
└─────────────────────────────────────────────────────┘
```

## Key Concept Preview: Refutability

Patterns come in two kinds:

| Kind | Description | Example |
|---|---|---|
| **Irrefutable** | Always matches; can never fail | `let x = 5;` |
| **Refutable** | May fail to match for some values | `if let Some(x) = val` |

- `let`, `for`, and function parameters only accept **irrefutable** patterns.
- `if let` and `while let` accept **refutable** patterns (and warn on irrefutable ones).
- `match` arms can be either, but the final arm is usually irrefutable (a catch-all).

This distinction is covered in depth in the next section.

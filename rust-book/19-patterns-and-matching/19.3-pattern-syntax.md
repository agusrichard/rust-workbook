# 19.3 - Pattern Syntax

## Overview

This section covers all valid pattern syntax in Rust — from simple literal matching to advanced binding with `@`. Patterns are the mechanism Rust uses to match against the structure of types, and mastering pattern syntax unlocks expressive, concise, and safe code.

---

## 1. Matching Literals

Patterns can match directly against concrete literal values.

```rust
fn main() {
    let x = 1;

    match x {
        1 => println!("one"),
        2 => println!("two"),
        3 => println!("three"),
        _ => println!("anything"),
    }
}
```

Prints `one` because `x` is `1`. Useful when code should react to a specific concrete value.

---

## 2. Matching Named Variables

Named variables in patterns are irrefutable — they match any value. Inside a `match`, each arm opens a new scope, so a variable in a pattern *shadows* any outer variable with the same name.

```rust
fn main() {
    let x = Some(5);
    let y = 10;

    match x {
        Some(50) => println!("Got 50"),
        Some(y) => println!("Matched, y = {y}"),   // new `y`, shadows outer `y`
        _ => println!("Default case, x = {x:?}"),
    }

    println!("at the end: x = {x:?}, y = {y}");    // outer `y` is still 10
}
```

The second arm's `y` is a new variable that captures `Some`'s inner value — it does **not** compare against the outer `y = 10`.

---

## 3. Multiple Patterns with `|`

The `|` operator is the pattern *or* operator — it matches if any of the listed patterns match.

```rust
fn main() {
    let x = 1;

    match x {
        1 | 2 => println!("one or two"),
        3 => println!("three"),
        _ => println!("anything"),
    }
}
```

Prints `one or two`.

---

## 4. Range Matching with `..=`

`..=` matches an inclusive range of values. Works with numeric types and `char`.

```rust
fn main() {
    let x = 5;

    match x {
        1..=5 => println!("one through five"),
        _ => println!("something else"),
    }
}
```

```rust
fn main() {
    let x = 'c';

    match x {
        'a'..='j' => println!("early ASCII letter"),
        'k'..='z' => println!("late ASCII letter"),
        _ => println!("something else"),
    }
}
```

Rust can determine at compile time whether a range is empty, so ranges are only valid for `char` and numeric types.

## 5. Destructuring

### 5.1 Structs

Extract field values using patterns in a `let` statement:

```rust
struct Point {
    x: i32,
    y: i32,
}

fn main() {
    let p = Point { x: 0, y: 7 };

    let Point { x: a, y: b } = p;   // rename fields to a, b
    assert_eq!(0, a);
    assert_eq!(7, b);
}
```

Shorthand: when variable names match field names, you can omit the alias:

```rust
fn main() {
    let p = Point { x: 0, y: 7 };

    let Point { x, y } = p;   // x and y created directly
    assert_eq!(0, x);
    assert_eq!(7, y);
}
```

Destructure with literal values to match specific field values:

```rust
fn main() {
    let p = Point { x: 0, y: 7 };

    match p {
        Point { x, y: 0 } => println!("On the x axis at {x}"),
        Point { x: 0, y } => println!("On the y axis at {y}"),
        Point { x, y } => println!("On neither axis: ({x}, {y})"),
    }
}
```

### 5.2 Enums

The pattern structure mirrors how the enum variant stores data:

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}

fn main() {
    let msg = Message::ChangeColor(0, 160, 255);

    match msg {
        Message::Quit => {
            println!("The Quit variant has no data to destructure.");
        }
        Message::Move { x, y } => {
            println!("Move in the x direction {x} and in the y direction {y}");
        }
        Message::Write(text) => {
            println!("Text message: {text}");
        }
        Message::ChangeColor(r, g, b) => {
            println!("Change color to red {r}, green {g}, and blue {b}");
        }
    }
}
```

### 5.3 Nested Structs and Enums

Patterns can destructure multiple levels of nesting:

```rust
enum Color {
    Rgb(i32, i32, i32),
    Hsv(i32, i32, i32),
}

enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(Color),
}

fn main() {
    let msg = Message::ChangeColor(Color::Hsv(0, 160, 255));

    match msg {
        Message::ChangeColor(Color::Rgb(r, g, b)) => {
            println!("Change color to red {r}, green {g}, and blue {b}");
        }
        Message::ChangeColor(Color::Hsv(h, s, v)) => {
            println!("Change color to hue {h}, saturation {s}, value {v}");
        }
        _ => (),
    }
}
```

### 5.4 Mixed Complex Destructuring

Structs and tuples can be nested and destructured together:

```rust
fn main() {
    struct Point {
        x: i32,
        y: i32,
    }

    let ((feet, inches), Point { x, y }) = ((3, 10), Point { x: 3, y: -10 });
}
```

## 6. Ignoring Values

### 6.1 `_` — Wildcard (no binding)

`_` matches any value without binding it. Useful in function signatures and as a catch-all:

```rust
fn foo(_: i32, y: i32) {
    println!("This code only uses the y parameter: {y}");
}

fn main() {
    foo(3, 4);
}
```

`_` inside a pattern ignores specific parts:

```rust
fn main() {
    let mut setting_value = Some(5);
    let new_setting_value = Some(10);

    match (setting_value, new_setting_value) {
        (Some(_), Some(_)) => {
            println!("Can't overwrite an existing customized value");
        }
        _ => {
            setting_value = new_setting_value;
        }
    }

    println!("setting is {setting_value:?}");
}
```

Ignore specific positions in a tuple:

```rust
fn main() {
    let numbers = (2, 4, 8, 16, 32);

    match numbers {
        (first, _, third, _, fifth) => {
            println!("Some numbers: {first}, {third}, {fifth}");
        }
    }
}
```

### 6.2 `_x` — Suppress Unused Variable Warnings

A name starting with `_` suppresses the "unused variable" warning, **but still binds the value** (and may move ownership):

```rust
fn main() {
    let _x = 5;   // no warning
    let y = 10;   // warning: unused variable `y`
}
```

**Important**: `_x` still binds, so this fails to compile because `s` is moved into `_s`:

```rust
fn main() {
    let s = Some(String::from("Hello!"));

    if let Some(_s) = s {
        println!("found a string");
    }

    println!("{s:?}");   // error: s was moved
}
```

Use plain `_` when you need to avoid moving:

```rust
fn main() {
    let s = Some(String::from("Hello!"));

    if let Some(_) = s {
        println!("found a string");
    }

    println!("{s:?}");   // fine: s was never moved
}
```

### 6.3 `..` — Ignore Remaining Parts

`..` expands to match all remaining (unspecified) parts of a struct or tuple:

```rust
fn main() {
    struct Point {
        x: i32,
        y: i32,
        z: i32,
    }

    let origin = Point { x: 0, y: 0, z: 0 };

    match origin {
        Point { x, .. } => println!("x is {x}"),
    }
}
```

With tuples, `..` can appear in the middle:

```rust
fn main() {
    let numbers = (2, 4, 8, 16, 32);

    match numbers {
        (first, .., last) => {
            println!("Some numbers: {first}, {last}");
        }
    }
}
```

`..` must be **unambiguous** — using it in a way where Rust cannot determine which values belong to which variable is a compile error:

```rust
// ERROR: ambiguous use of ..
fn main() {
    let numbers = (2, 4, 8, 16, 32);

    match numbers {
        (.., second, ..) => {
            println!("Some numbers: {second}")
        },
    }
}
```

## 7. Match Guards

A *match guard* is an extra `if` condition after a pattern. The arm only executes when both the pattern and the guard are satisfied. This allows expressing conditions that patterns alone cannot represent.

```rust
fn main() {
    let num = Some(4);

    match num {
        Some(x) if x % 2 == 0 => println!("The number {x} is even"),
        Some(x) => println!("The number {x} is odd"),
        None => (),
    }
}
```

### Solving Variable Shadowing with Guards

Match guards can reference *outer* variables (without shadowing them) by using a new pattern variable name and testing equality in the guard:

```rust
fn main() {
    let x = Some(5);
    let y = 10;

    match x {
        Some(50) => println!("Got 50"),
        Some(n) if n == y => println!("Matched, n = {n}"),   // compares to outer y
        _ => println!("Default case, x = {x:?}"),
    }

    println!("at the end: x = {x:?}, y = {y}");
}
```

### Guards with the `|` Operator

When `|` is used in a pattern, the guard applies to **all** alternatives:

```rust
fn main() {
    let x = 4;
    let y = false;

    match x {
        4 | 5 | 6 if y => println!("yes"),   // guard applies to 4, 5, AND 6
        _ => println!("no"),
    }
}
```

The precedence is `(4 | 5 | 6) if y`, not `4 | 5 | (6 if y)`.

---

## 8. `@` Bindings

The `@` operator lets you **capture** a value into a variable *while simultaneously testing it* against a pattern or range.

```rust
fn main() {
    enum Message {
        Hello { id: i32 },
    }

    let msg = Message::Hello { id: 5 };

    match msg {
        Message::Hello { id: id @ 3..=7 } => {
            println!("Found an id in range: {id}")   // id is bound AND tested
        }
        Message::Hello { id: 10..=12 } => {
            println!("Found an id in another range")  // id not captured, can't use it
        }
        Message::Hello { id } => println!("Found some other id: {id}"),
    }
}
```

In the second arm (`10..=12`), only the range test is performed — `id` is not bound, so it cannot be used in the arm body. `@` solves this by combining the bind and the test.

---

## Key Distinctions Summary

| Syntax | Binds? | Notes |
|---|---|---|
| `_` | No | Wildcard, no binding, no move |
| `_x` | Yes | Suppresses warning, still moves ownership |
| `..` | No | Ignores remaining fields/elements |
| `x @ range` | Yes | Binds and tests simultaneously |
| `\| ` in pattern | — | Matches any alternative |
| `if guard` | — | Extra condition; applies to all `\|` alternatives |

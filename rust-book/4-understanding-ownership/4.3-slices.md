# The Slice Type

Slices let you reference a contiguous sequence of elements in a collection rather than the whole collection. A slice is a kind of reference, so it is a non-owning pointer.

## The Problem: Syncing Indices

Without slices, we often resort to returning indices to refer to parts of a data structure. This is error-prone because the index is just a number; it is not tied to the state of the data it refers to.

**Example: The First Word Problem (Unsafe Approach)**
Here is a function that tries to identify the first word in a string by returning the index of the first space:

```rust
fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

```

This approach is brittle. If we modify the string after calculating the index, the index becomes invalid, but the compiler won't stop us from using it:

```rust
fn main() {
    let mut s = String::from("hello world");
    let word = first_word(&s); // word will be 5

    s.clear(); // s is now "", but word is still 5!

    // word is now invalid, but used detached from s
}

```

## String Slices

A **String Slice** (`&str`) is a reference to part of a `String`. It solves the synchronization problem by tying the reference directly to the valid range of data.

```rust
let s = String::from("hello world");

let hello: &str = &s[0..5];
let world: &str = &s[6..11];

```

### Internal Representation

Slices are "fat pointers". Unlike a regular reference (which is just an address), a slice consists of two items:

1. A **pointer** to the starting byte.
2. The **length** of the slice.

### Range Syntax

Rust provides syntactic sugar for ranges:

- `[0..2]` is the same as `[..2]` (starts from beginning).
- `[3..len]` is the same as `[3..]` (goes to the end).
- `[0..len]` is the same as `[..]` (entire string).

### Fixing the First Word Problem

By returning a slice (`&str`), the compiler ensures the reference remains valid. If we clear the string, the slice becomes invalid, and the compiler throws an error.

```rust
fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }

    &s[..]
}

```

Now, the previous bug is caught at compile time:

```rust
fn main() {
    let mut s = String::from("hello world");
    let word = first_word(&s); // Immutable borrow occurs here

    s.clear(); // Error! Cannot mutate s because it is borrowed by word

    println!("the first word is: {}", word);
}

```

## String Literals Are Slices

String literals are stored inside the binary. The type of a string literal is `&str`: it is a slice pointing to that specific location in the binary.

```rust
let s = "Hello, world!"; // s: &str

```

## String Slices as Parameters

Using `&str` as a function parameter allows the function to accept both `String` and `&str` (string literals), making the API more flexible.

```rust
fn first_word(s: &str) -> &str { ... }

fn main() {
    let my_string = String::from("hello world");

    // Works on String slices
    let word = first_word(&my_string[0..6]);
    // Works on references to String (implicit conversion)
    let word = first_word(&my_string);
    // Works on string literals
    let word = first_word("hello world");
}

```

## Other Slices

Slices work for other collections too, such as arrays.

```rust
let a = [1, 2, 3, 4, 5];
let slice = &a[1..3];
assert_eq!(slice, &[2, 3]);

```

This slice has the type `&[i32]` and stores a reference to the first element and the length, just like string slices.

### Summary

- **Slices** refer to a contiguous sequence of elements.
- They are **fat pointers** (pointer + length).
- They prevent bugs involving invalid indices by ensuring the data they reference is valid for the slice's lifetime.

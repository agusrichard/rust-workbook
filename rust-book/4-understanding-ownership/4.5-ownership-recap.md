# Ownership Recap

This chapter reviews the critical concepts of ownership, borrowing, and slices, which form the foundation for Rust's memory safety without garbage collection.

## Ownership vs. Garbage Collection

Most languages (Python, Java, Go) use **Garbage Collection (GC)** to manage memory.

- **Pros:** Avoids undefined behavior (like use-after-free) and manual memory management.
- **Cons:** Can have unpredictable performance overhead and makes it difficult to predict when memory is freed. It also obscures which variables point to which data, leading to accidental mutations (e.g., modifying a copy of a list also modifies the original).

**Rust's Approach:**
Rust makes pointers and memory ownership **explicit**.

- **Predictability:** You know exactly when data is deallocated (when the owner goes out of scope).
- **Performance:** No runtime GC overhead.
- **Safety:** The compiler prevents data races and undefined behavior.

## Ownership at Runtime

- **Stack:** Stores local variables (fixed size). Pointers (references/boxes) live here.
- **Heap:** Stores dynamic data (e.g., contents of a `String` or `Box`).
- **Slices:** "Fat pointers" consisting of a pointer to data and a length. They refer to a contiguous sequence (like a substring).

## Ownership at Compile-Time (Permissions)

Rust tracks three types of permissions for every variable:

- **Read (R)**: Can copy/read data.
- **Write (W)**: Can mutate data.
- **Own (O)**: Can move or drop data.

### Moves

- Moving a variable (e.g., `let y = x` for non-copy types) requires **RO** permissions.
- After the move, the original variable loses **all** permissions and cannot be used.

### Borrowing (References)

- **Immutable Borrow (`&T`)**:
- Creates an immutable reference.
- **Original:** Temporarily loses **W** and **O** permissions (cannot mutate or move).
- **Reference:** Gains **R**.

- **Mutable Borrow (`&mut T`)**:
- Creates a unique mutable reference.
- **Original:** Temporarily loses **all** permissions (cannot access at all).
- **Reference:** Gains **R** and **W**.

## Safety Guarantees

These rules prevent specific undefined behaviors:

1. **Use-After-Free:** You cannot use a reference to data that has been dropped. (Checked by lifetimes and ownership).
2. **Double-Free:** You cannot free the same memory twice. (Prevented because only one variable "owns" the data).
3. **Data Races/Iterator Invalidation:** You cannot mutate a collection (like `Vec`) while holding an immutable reference to its elements.

**Example: Iterator Invalidation (Prevented)**

```rust
let mut v = vec![1, 2, 3];
let n = &v[0]; // Immutable borrow
v.push(4);     // Mutation (requires W, but v lost W due to borrow)
println!("{n}"); // Error!

```

Rust rejects this because `push` might reallocate the vector, leaving `n` pointing to freed memory.

# What Is Ownership?

Ownership is a core discipline in Rust designed to ensure memory safety without a garbage collector. It works by preventing **undefined behavior** at compile time.

## Safety is the Absence of Undefined Behavior

Rust ensures safety by checking programs at compile-time to prevent operations that could lead to crashes or security vulnerabilities.

**Example: Unsafe Code (Undefined Behavior)**
In many languages, accessing a variable before it is defined might crash at runtime. Rust catches this at compile time.

```rust
fn read(y: bool) {
    if y {
        println!("y is true!");
    }
}

fn main() {
    read(x); // Error: x isn't defined!
    let x = true;
}

```

If this were allowed to run, `read(x)` would access memory where `x` _should_ be but isn't yet. This leads to undefined behavior, where the program might read random data (like `100` or `0x1337BEEF` instead of `0` or `1`).

## Variables Live in the Stack

Variables in Rust live in **frames** on the **stack**. A frame is a mapping of variables to values for a single scope (like a function). When a function returns, its frame is deallocated (dropped).

**Example: Copying Stack Data**
Simple values like integers are copied when assigned.

```rust
fn main() {
    let a = 5;
    let mut b = a; // Value of 'a' is copied into 'b'
    b += 1;
    // 'a' remains 5, 'b' becomes 6
}

```

## Boxes Live in the Heap

Copying large amounts of data (like an array of 1 million elements) on the stack is inefficient. To solve this, Rust uses **pointers** to manage data on the **heap**. The `Box` type constructs a pointer to heap-allocated data.

**Example: Heap Allocation with Box**

```rust
fn main() {
    let a = Box::new([0; 1_000_000]); // 'a' points to the array on the heap
    let b = a; // Ownership moves to 'b'
}

```

## Ownership and Moves

To prevent memory errors (like freeing the same memory twice), Rust enforces **Ownership Rules**:

1. **Move Semantics**: When `let b = a` executes for heap data (like a Box), ownership moves from `a` to `b`.
2. **Deallocation**: Memory is freed only when the _owner_ (`b`) goes out of scope.

If Rust allowed both `a` and `b` to own the data, both might try to free it, causing a "double free" error.

## Collections Use Boxes

Complex data structures like `String`, `Vec`, and `HashMap` use boxes internally to manage dynamic data.

**Example: Moving Strings**

```rust
fn main() {
    let first = String::from("Ferris");
    let full = add_suffix(first); // Ownership of 'first' moves to function
    println!("{full}");
}

fn add_suffix(mut name: String) -> String {
    name.push_str(" Jr."); // Heap allocation may resize here
    name // Ownership moves back to caller
}

```

## Variables Cannot Be Used After Being Moved

Once ownership is moved, the original variable cannot be used. This prevents "use after free" errors.

**Example: Compile-Time Error on Move**

```rust
fn main() {
    let first = String::from("Ferris");
    let full = add_suffix(first);
    println!("{full}, originally {first}"); // Error: 'first' was moved!
}

```

Rust rejects this because `first` points to memory that might have been deallocated or modified by `add_suffix`.

## Cloning Avoids Moves

If you want to keep the original variable, you can use `.clone()` to create a deep copy of the heap data.

**Example: Cloning**

```rust
fn main() {
    let first = String::from("Ferris");
    let first_clone = first.clone(); // Deep copy of heap data
    let full = add_suffix(first_clone);
    println!("{full}, originally {first}"); // Safe: 'first' was not moved
}

```

## Summary of Ownership Rules

1. All heap data must be owned by exactly one variable.
2. Rust deallocates heap data once its owner goes out of scope.
3. Ownership can be transferred via **moves** (assignments, function calls).
4. Heap data can only be accessed through its current owner.

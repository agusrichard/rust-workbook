# Using Message Passing to Transfer Data Between Threads

## Overview

This section introduces **message passing** as a safe concurrency pattern in Rust. Instead of sharing memory directly between threads, threads communicate by sending data through **channels** — a transmitter sends values, and a receiver collects them. Rust's ownership system guarantees that once data is sent, the sender no longer has access to it, eliminating a whole class of data-race bugs at compile time.

> "Do not communicate by sharing memory; instead, share memory by communicating."

---

## Key Concepts

### Channels

A channel is a one-directional pipe with two endpoints:
- **Transmitter (`tx`)** — the sending side (upstream)
- **Receiver (`rx`)** — the receiving side (downstream)

Data flows from `tx` to `rx`. A channel is closed when either endpoint is dropped.

### MPSC: Multiple Producer, Single Consumer

Rust's standard library channel (`std::sync::mpsc`) supports **multiple producers but only one consumer**. You can clone the transmitter to create multiple sending threads, but there can only be one receiver.

---

## Code Examples

### Basic Channel Creation

```rust
use std::sync::mpsc;

fn main() {
    let (tx, rx) = mpsc::channel();
}
```

`mpsc::channel()` returns a tuple of `(Sender<T>, Receiver<T>)`. The type `T` is inferred from the first value sent.

---

### Sending from a Spawned Thread

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        let val = String::from("hi");
        tx.send(val).unwrap();
    });
}
```

`tx` is moved into the closure so the spawned thread owns it. `send()` returns a `Result` — it fails if the receiver has been dropped.

---

### Receiving in the Main Thread

```rust
use std::sync::mpsc;
use std::thread;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        let val = String::from("hi");
        tx.send(val).unwrap();
    });

    let received = rx.recv().unwrap();
    println!("Got: {received}");
}
```

**Output:**
```
Got: hi
```

`recv()` **blocks** the calling thread until a message arrives. It returns `Result<T, RecvError>`.

---

### Ownership Enforced: No Use After Send

Attempting to use a value after sending it is a compile-time error:

```rust
thread::spawn(move || {
    let val = String::from("hi");
    tx.send(val).unwrap();
    println!("val is {val}"); // ERROR: value was moved into send()
});
```

**Compiler error:**
```
error[E0382]: borrow of moved value: `val`
 --> src/main.rs:10:26
  |
8  |         let val = String::from("hi");
   |             --- move occurs because `val` has type `String`
9  |         tx.send(val).unwrap();
   |                 --- value moved here
10 |        println!("val is {val}");
   |                      ^^^^^ value borrowed here after move
```

`send()` takes ownership of the value. The compiler prevents the sender from using it afterwards, ensuring the receiver always gets valid, unmodified data.

---

### Sending Multiple Messages

The receiver can be iterated like an iterator — it yields each message as it arrives and stops when the channel is closed (i.e., the transmitter is dropped):

```rust
use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel();

    thread::spawn(move || {
        let vals = vec![
            String::from("hi"),
            String::from("from"),
            String::from("the"),
            String::from("thread"),
        ];

        for val in vals {
            tx.send(val).unwrap();
            thread::sleep(Duration::from_secs(1));
        }
    });

    for received in rx {
        println!("Got: {received}");
    }
}
```

**Output:**
```
Got: hi
Got: from
Got: the
Got: thread
```

The main thread blocks on each iteration, waiting for the next message. The loop ends when `tx` is dropped (after the spawned thread exits).

---

### Multiple Producers

Clone `tx` to create additional senders. All clones send to the same receiver:

```rust
use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel();

    let tx1 = tx.clone();
    thread::spawn(move || {
        let vals = vec![
            String::from("hi"),
            String::from("from"),
            String::from("the"),
            String::from("thread"),
        ];

        for val in vals {
            tx1.send(val).unwrap();
            thread::sleep(Duration::from_secs(1));
        }
    });

    thread::spawn(move || {
        let vals = vec![
            String::from("more"),
            String::from("messages"),
            String::from("for"),
            String::from("you"),
        ];

        for val in vals {
            tx.send(val).unwrap();
            thread::sleep(Duration::from_secs(1));
        }
    });

    for received in rx {
        println!("Got: {received}");
    }
}
```

**Sample Output** (order may vary):
```
Got: hi
Got: more
Got: from
Got: messages
Got: for
Got: the
Got: thread
Got: you
```

The interleaving of messages from both threads is non-deterministic.

## Receiver Methods

| Method | Behaviour |
|--------|-----------|
| `recv()` | **Blocks** until a message is available; returns `Result<T, RecvError>` |
| `try_recv()` | **Non-blocking**; returns `Ok(T)` immediately if a message is ready, or `Err` if not |

`try_recv()` is useful when the receiving thread has other work to do while waiting (e.g., polling in a loop).

---

## Summary

| Concept | Key Point |
|---------|-----------|
| `mpsc::channel()` | Creates a `(Sender, Receiver)` pair |
| `send(val)` | Moves `val` into the channel; caller loses ownership |
| `recv()` | Blocks until a message arrives |
| `try_recv()` | Non-blocking receive |
| Iterating `rx` | Yields messages until all senders are dropped |
| `tx.clone()` | Creates an additional sender (multiple producers) |

Rust's ownership model makes message passing inherently safe: `send()` consumes the value, so there is no shared mutable state — the compiler guarantees that only one thread owns the data at any given time.

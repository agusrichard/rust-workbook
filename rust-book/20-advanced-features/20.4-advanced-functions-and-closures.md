# 20.4 - Advanced Functions and Closures

## Overview

This section covers two advanced topics related to functions and closures in Rust:
1. **Function Pointers** — passing functions as arguments using the `fn` type
2. **Returning Closures** — how to return closures from functions using `impl Trait` or trait objects

---

## Function Pointers

You can pass regular functions as arguments to other functions using **function pointers**. The type is written as `fn` (lowercase), which is a concrete type — not to be confused with the `Fn` closure trait (uppercase).

### Syntax

```rust
fn add_one(x: i32) -> i32 {
    x + 1
}

fn do_twice(f: fn(i32) -> i32, arg: i32) -> i32 {
    f(arg) + f(arg)
}

fn main() {
    let answer = do_twice(add_one, 5);
    println!("The answer is: {answer}"); // The answer is: 12
}
```

Here, `do_twice` takes a function pointer `f` of type `fn(i32) -> i32` and an `i32` argument. We pass `add_one` (without parentheses — just the name) as the function pointer.

### `fn` vs `Fn`

| Feature | `fn` (function pointer) | `Fn` (closure trait) |
|---|---|---|
| Kind | Concrete type | Trait |
| Accepts | Named functions | Closures and functions |
| Implements closure traits | Yes — all three (`Fn`, `FnMut`, `FnOnce`) | N/A |

Because `fn` implements all three closure traits, you can always pass a function pointer where a closure is expected. This is particularly useful when interfacing with languages like C that don't support closures.

### Using Function Pointers with Iterators

Function pointers can be passed to iterator adapters like `map()`, just like closures:

```rust
// Using a closure
let list_of_numbers = vec![1, 2, 3];
let list_of_strings: Vec<String> =
    list_of_numbers.iter().map(|i| i.to_string()).collect();

// Using a function pointer
let list_of_numbers = vec![1, 2, 3];
let list_of_strings: Vec<String> =
    list_of_numbers.iter().map(ToString::to_string).collect();
```

Both produce the same result. `ToString::to_string` is used here via the fully qualified syntax because multiple `to_string` implementations exist.

### Enum Variant Initializers as Function Pointers

Enum variants that hold data act as initializer functions, and their names can be used as function pointers:

```rust
#[derive(Debug)]
enum Status {
    Value(u32),
    Stop,
}

let list_of_statuses: Vec<Status> =
    (0u32..20).map(Status::Value).collect();
```

`Status::Value` is treated as `fn(u32) -> Status`, so it can be passed directly to `map()`. This is more concise than writing a closure like `|i| Status::Value(i)`.

## Returning Closures

Closures are represented by traits (`Fn`, `FnMut`, `FnOnce`) — they don't have a single concrete type that can be named directly in a return position. This means you **cannot** return a closure the same way you return a concrete type.

### Approach 1: `impl Trait`

The simplest approach for a single returned closure type:

```rust
fn returns_closure() -> impl Fn(i32) -> i32 {
    |x| x + 1
}
```

This works well when the function always returns the same kind of closure. Rust infers the concrete type at compile time.

**Limitation**: If you need to return different closures from different branches, each branch produces a distinct opaque type, causing a compile error:

```rust
// This does NOT compile
fn returns_closure(a: i32) -> impl Fn(i32) -> i32 {
    if a > 0 {
        |x| x + 1   // opaque type #1
    } else {
        |x| x - 1   // opaque type #2 — ERROR: incompatible types
    }
}
```

### Approach 2: Trait Objects (`Box<dyn Fn>`)

Use a **boxed trait object** when you need to return closures of potentially different concrete types from the same function:

```rust
fn returns_closure(a: i32) -> Box<dyn Fn(i32) -> i32> {
    if a > 0 {
        Box::new(|x| x + 1)
    } else {
        Box::new(|x| x - 1)
    }
}
```

`Box<dyn Fn(i32) -> i32>` is a trait object stored on the heap. It erases the concrete type, so both branches can return the same type.

This is also useful for storing heterogeneous closures in a collection:

```rust
fn main() {
    let operations: Vec<Box<dyn Fn(i32) -> i32>> = vec![
        Box::new(|x| x + 1),
        Box::new(|x| x * 2),
        Box::new(|x| x - 3),
    ];

    let mut value = 5;
    for op in &operations {
        value = op(value);
    }
    println!("{value}"); // ((5 + 1) * 2) - 3 = 9
}
```

### `impl Trait` vs `Box<dyn Fn>` Comparison

| | `impl Fn(...)` | `Box<dyn Fn(...)>` |
|---|---|---|
| Dispatch | Static (compile-time) | Dynamic (runtime) |
| Heap allocation | No | Yes |
| Multiple closure types | No | Yes |
| Collection storage | No | Yes |
| Performance | Faster | Slight overhead |

---

## Key Takeaways

- `fn` is a **concrete type** for function pointers; `Fn` is a **trait** for closures.
- Function pointers implement `Fn`, `FnMut`, and `FnOnce`, so they work anywhere a closure is expected.
- Enum variant constructors (e.g., `Status::Value`) can be used as function pointers.
- Use `impl Fn(...)` to return a closure when only one concrete closure type is possible.
- Use `Box<dyn Fn(...)>` when you need to return different closure types or store closures in a collection.

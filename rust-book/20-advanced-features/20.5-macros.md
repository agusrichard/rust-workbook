# 20.5 - Macros

## Overview

Macros are a form of **metaprogramming** — code that writes other code. Rust has two major families of macros:

1. **Declarative macros** (`macro_rules!`) — pattern-based, match-and-replace style
2. **Procedural macros** — function-like, operate on token streams; three subtypes:
   - Custom `#[derive]` macros
   - Attribute-like macros
   - Function-like macros

---

## Macros vs Functions

| Feature | Macros | Functions |
|---|---|---|
| Parameter count | Variable | Fixed (declared in signature) |
| Compile-time trait implementation | Yes | No |
| Definition location | Must be defined/imported before use | Can be defined anywhere |
| Complexity | Higher (write code that writes code) | Lower |

The key advantage of macros: they expand **before** the compiler interprets meaning, so they can do things functions can't — like implementing a trait on a type at compile time.

The key downside: macro definitions are harder to read, write, and maintain.

---

## Declarative Macros (`macro_rules!`)

Also called "macros by example" or "macro_rules! macros." They work like a `match` expression on Rust source code structure — comparing patterns against code and replacing matches with other code.

### The `vec!` Macro

```rust
// Usage
let v: Vec<u32> = vec![1, 2, 3];
```

A simplified definition of how `vec!` is implemented:

```rust
#[macro_export]
macro_rules! vec {
    ( $( $x:expr ),* ) => {
        {
            let mut temp_vec = Vec::new();
            $(
                temp_vec.push($x);
            )*
            temp_vec
        }
    };
}
```

### Pattern Syntax Breakdown

```
( $( $x:expr ),* )
```

| Part | Meaning |
|---|---|
| `( ... )` | Wraps the entire pattern |
| `$( ... )` | Captures repeated items |
| `$x:expr` | Captures any Rust expression, binds it to `$x` |
| `,` | Literal comma separator between repetitions |
| `*` | Zero or more repetitions |

In the body:
- `$( temp_vec.push($x); )*` — expands once per captured `$x`

### What the Macro Expands To

When called as `vec![1, 2, 3]`, the macro expands to:

```rust
{
    let mut temp_vec = Vec::new();
    temp_vec.push(1);
    temp_vec.push(2);
    temp_vec.push(3);
    temp_vec
}
```

> Note: `#[macro_export]` makes the macro available when the crate is imported. Without it, the macro stays private.

> For deeper study, see "The Little Book of Rust Macros" (started by Daniel Keep, continued by Lukas Wirth).

## Procedural Macros

Procedural macros act more like functions — they accept a `TokenStream` as input and produce a `TokenStream` as output. They don't pattern-match source; they manipulate token streams directly using Rust code.

```
Input TokenStream → [macro function] → Output TokenStream
```

**Important constraint:** Procedural macro definitions must live in their own crate with `proc-macro = true` set in `Cargo.toml`.

### General Shape

```rust
use proc_macro::TokenStream;

#[some_attribute]
pub fn some_name(input: TokenStream) -> TokenStream {
    // transform input into output
}
```

## Custom `derive` Macros

These let users write `#[derive(YourTrait)]` on a struct or enum to automatically get a default trait implementation — without writing it manually.

### Goal

Allow users to write:

```rust
use hello_macro::HelloMacro;
use hello_macro_derive::HelloMacro;

#[derive(HelloMacro)]
struct Pancakes;

fn main() {
    Pancakes::hello_macro(); // prints: Hello, Macro! My name is Pancakes!
}
```

Instead of manually writing:

```rust
use hello_macro::HelloMacro;

struct Pancakes;

impl HelloMacro for Pancakes {
    fn hello_macro() {
        println!("Hello, Macro! My name is Pancakes!");
    }
}

fn main() {
    Pancakes::hello_macro();
}
```

### Step 1: Define the Trait (in `hello_macro` crate)

```rust
pub trait HelloMacro {
    fn hello_macro();
}
```

### Step 2: Create the Derive Macro (in `hello_macro_derive` crate)

**`Cargo.toml` for the derive crate:**

```toml
[lib]
proc-macro = true

[dependencies]
syn = "2.0"
quote = "1.0"
```

**`src/lib.rs`:**

```rust
use proc_macro::TokenStream;
use quote::quote;

#[proc_macro_derive(HelloMacro)]
pub fn hello_macro_derive(input: TokenStream) -> TokenStream {
    // Parse the input tokens into a syntax tree
    let ast = syn::parse(input).unwrap();
    impl_hello_macro(&ast)
}

fn impl_hello_macro(ast: &syn::DeriveInput) -> TokenStream {
    let name = &ast.ident; // the name of the struct/enum
    let generated = quote! {
        impl HelloMacro for #name {
            fn hello_macro() {
                println!("Hello, Macro! My name is {}!", stringify!(#name));
            }
        }
    };
    generated.into()
}
```

### Step 3: Use in a Project

**`Cargo.toml` for a user's crate:**

```toml
[dependencies]
hello_macro = { path = "../hello_macro" }
hello_macro_derive = { path = "../hello_macro/hello_macro_derive" }
```

### Key Crates

| Crate | Role |
|---|---|
| `proc_macro` | Built into Rust; provides the `TokenStream` type |
| `syn` | Parses a `TokenStream` into a manipulable AST (`DeriveInput`, `Ident`, etc.) |
| `quote` | Converts AST/data structures back into `TokenStream` (Rust code) |

### How `impl_hello_macro` Works

1. `ast.ident` — extracts the identifier (name) of the annotated type
2. `quote! { ... }` — defines the Rust code to generate, using `#name` as a template variable
3. `stringify!(#name)` — converts the identifier to a string literal **at compile time** (more efficient than `format!`, which would require a heap allocation at runtime)
4. `.into()` — converts `quote!`'s output into the required `TokenStream`

### Flow Diagram

```
User writes:               #[derive(HelloMacro)]
                           struct Pancakes;
                                  |
                                  v
hello_macro_derive::hello_macro_derive(TokenStream)
                                  |
                     syn::parse() → DeriveInput
                                  |
                     quote! { impl HelloMacro for Pancakes { ... } }
                                  |
                                  v
Compiler receives:         impl HelloMacro for Pancakes {
                               fn hello_macro() {
                                   println!("Hello, Macro! My name is Pancakes!");
                               }
                           }
```

## Attribute-Like Macros

Similar to custom derive macros, but more flexible:
- Custom `derive` only works on structs and enums
- Attribute-like macros work on **any item** — including functions

### Example Usage

```rust
#[route(GET, "/")]
fn index() {
    // ...
}
```

### Macro Definition Signature

```rust
#[proc_macro_attribute]
pub fn route(attr: TokenStream, item: TokenStream) -> TokenStream {
    // attr = the contents of the attribute: GET, "/"
    // item = the body of the item the attribute is attached to (fn index)
}
```

Two `TokenStream` parameters:
- `attr` — the contents inside the attribute parentheses (e.g., `GET, "/"`)
- `item` — the item the attribute is applied to (e.g., the whole `fn index() { ... }`)

Otherwise, attribute-like macros work the same as custom derive macros — defined in a `proc-macro` crate, returning a `TokenStream`.

---

## Function-Like Macros

These look like function calls but are more powerful — they can accept an arbitrary number of arguments or even arbitrary token streams.

### Example Usage

```rust
let sql = sql!(SELECT * FROM posts WHERE id=1);
```

This could validate SQL at compile time — something a regular function call cannot do.

### Macro Definition Signature

```rust
#[proc_macro]
pub fn sql(input: TokenStream) -> TokenStream {
    // parse and validate the SQL tokens
}
```

Unlike `macro_rules!` (which only supports match-like syntax), function-like procedural macros can run arbitrary Rust code to process the token stream.

---

## Summary of All Macro Types

| Type | Defined with | Works on | Use case |
|---|---|---|---|
| Declarative (`macro_rules!`) | `macro_rules!` | Any code | Pattern-based code generation (e.g., `vec!`, `println!`) |
| Custom `derive` | `#[proc_macro_derive]` | Structs, enums | Auto-implement traits |
| Attribute-like | `#[proc_macro_attribute]` | Any item (fn, struct, etc.) | Custom annotations with code generation |
| Function-like | `#[proc_macro]` | Token streams | Function-call-style macros (e.g., SQL validation) |

## Key Takeaways

- Macros are metaprogramming — they generate code at compile time.
- Declarative macros use pattern matching on code structure; procedural macros manipulate token streams with Rust code.
- All procedural macros live in a separate crate with `proc-macro = true`.
- Use `syn` to parse incoming `TokenStream`s into structured data; use `quote!` to generate output code.
- `stringify!(#name)` is preferred over `format!` in macros for compile-time string conversion without heap allocation.

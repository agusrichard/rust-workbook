# 20.2 - Advanced Traits

## High-Level Overview

This section dives into advanced trait features in Rust that go beyond the basics covered in Chapter 10. The topics covered are:

1. **Associated types** — type placeholders inside traits
2. **Default generic type parameters** — and operator overloading
3. **Disambiguation** — calling methods with the same name from different traits
4. **Supertraits** — traits that depend on other traits
5. **Newtype pattern** — working around the orphan rule

---

## Associated Types

Associated types connect a type placeholder to a trait, allowing method signatures within that trait to use the placeholder. The concrete type is specified by whoever implements the trait.

### The `Iterator` Example

```rust
pub trait Iterator {
    type Item;

    fn next(&mut self) -> Option<Self::Item>;
}
```

`Item` is the associated type — implementors fill it in with a concrete type.

```rust
struct Counter {
    count: u32,
}

impl Iterator for Counter {
    type Item = u32;

    fn next(&mut self) -> Option<Self::Item> {
        if self.count < 5 {
            self.count += 1;
            Some(self.count)
        } else {
            None
        }
    }
}
```

### Associated Types vs. Generics

| Feature | Generics | Associated Types |
|---|---|---|
| Multiple impls per type | Yes (`impl Foo<u32> for Bar`, `impl Foo<String> for Bar`) | No — one impl per type |
| Call-site type annotation needed | Often yes | No |
| Best used when | Multiple variations needed | One canonical type per trait impl |

Using generics instead of an associated type would require callers to annotate which `Item` type they want every time — associated types remove that burden.

## Default Generic Parameters and Operator Overloading

Default generic parameters use the syntax `<PlaceholderType=ConcreteType>`, letting implementors skip specifying the type when the default is correct.

### The `Add` Trait

```rust
trait Add<Rhs=Self> {
    type Output;

    fn add(self, rhs: Rhs) -> Self::Output;
}
```

`Rhs` defaults to `Self`, which covers the most common case: adding a type to itself.

### Adding Two Points (default `Rhs`)

```rust
use std::ops::Add;

#[derive(Debug, Copy, Clone, PartialEq)]
struct Point {
    x: i32,
    y: i32,
}

impl Add for Point {
    type Output = Point;

    fn add(self, other: Point) -> Point {
        Point {
            x: self.x + other.x,
            y: self.y + other.y,
        }
    }
}

fn main() {
    assert_eq!(
        Point { x: 1, y: 0 } + Point { x: 2, y: 3 },
        Point { x: 3, y: 3 }
    );
}
```

### Adding Different Types (custom `Rhs`)

```rust
use std::ops::Add;

struct Millimeters(u32);
struct Meters(u32);

impl Add<Meters> for Millimeters {
    type Output = Millimeters;

    fn add(self, other: Meters) -> Millimeters {
        Millimeters(self.0 + (other.0 * 1000))
    }
}
```

### Two Main Uses of Default Type Parameters

1. **Extend a type without breaking existing code** — new generic parameter can have a sensible default.
2. **Simplify the common case** — implementors only specify the type when they need to deviate.

## Disambiguating Between Identically Named Methods

Rust allows multiple traits to define methods with the same name, and a type can implement all of them. When names collide, you need explicit syntax to specify which one to call.

### Methods with `self` Parameters

```rust
trait Pilot {
    fn fly(&self);
}

trait Wizard {
    fn fly(&self);
}

struct Human;

impl Pilot for Human {
    fn fly(&self) {
        println!("This is your captain speaking.");
    }
}

impl Wizard for Human {
    fn fly(&self) {
        println!("Up!");
    }
}

impl Human {
    fn fly(&self) {
        println!("*waving arms furiously*");
    }
}

fn main() {
    let person = Human;
    Pilot::fly(&person);   // → "This is your captain speaking."
    Wizard::fly(&person);  // → "Up!"
    person.fly();          // → "*waving arms furiously*" (direct impl wins by default)
}
```

**Rule**: Rust defaults to the method directly on the type. To call a trait's version, use `TraitName::method(&value)`.

### Associated Functions (No `self`) — Fully Qualified Syntax

When methods don't take `self`, Rust has no receiver to help determine which impl to use. You must use the fully qualified syntax:

```
<Type as Trait>::function(receiver_if_method, next_arg, ...);
```

```rust
trait Animal {
    fn baby_name() -> String;
}

struct Dog;

impl Dog {
    fn baby_name() -> String {
        String::from("Spot")
    }
}

impl Animal for Dog {
    fn baby_name() -> String {
        String::from("puppy")
    }
}

fn main() {
    // Dog::baby_name()              → "Spot" (Dog's own impl)
    // Animal::baby_name()           → compile error (which type?)
    println!("A baby dog is called a {}", <Dog as Animal>::baby_name()); // → "puppy"
}
```

## Supertraits

A **supertrait** is a trait that another trait requires. If trait `B` has supertrait `A`, any type that implements `B` must also implement `A`.

```
OutlinePrint : fmt::Display
     ↑
 requires Display to be implemented too
```

### Example

```rust
use std::fmt;

trait OutlinePrint: fmt::Display {
    fn outline_print(&self) {
        let output = self.to_string();  // uses Display::to_string
        let len = output.len();
        println!("{}", "*".repeat(len + 4));
        println!("*{}*", " ".repeat(len + 2));
        println!("* {output} *");
        println!("*{}*", " ".repeat(len + 2));
        println!("{}", "*".repeat(len + 4));
    }
}
```

`outline_print` calls `self.to_string()`, which requires `Display`. The `: fmt::Display` supertrait bound enforces this at compile time.

### Implementing `OutlinePrint` for `Point`

```rust
struct Point {
    x: i32,
    y: i32,
}

impl fmt::Display for Point {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

impl OutlinePrint for Point {}

fn main() {
    let p = Point { x: 1, y: 3 };
    p.outline_print();
    // Output:
    // *********
    // *       *
    // * (1, 3) *
    // *       *
    // *********
}
```

If `Display` is not implemented for `Point`, the compiler will refuse to let `Point` implement `OutlinePrint`.

## The Newtype Pattern

The **orphan rule** says: you can implement a trait on a type only if either the trait or the type is local to your crate. This prevents implementing external traits on external types.

The **newtype pattern** works around this by wrapping the external type in a local tuple struct.

### Example: `Display` for `Vec<String>`

`Vec<T>` and `Display` are both from the standard library — you can't implement `Display` for `Vec<T>` directly. But you can wrap it:

```rust
use std::fmt;

struct Wrapper(Vec<String>);

impl fmt::Display for Wrapper {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "[{}]", self.0.join(", "))
    }
}

fn main() {
    let w = Wrapper(vec![String::from("hello"), String::from("world")]);
    println!("w = {w}");  // → w = [hello, world]
}
```

`self.0` accesses the inner `Vec<String>` through the tuple struct.

### Trade-offs

| Aspect | Detail |
|---|---|
| Runtime cost | Zero — newtype wrappers are erased at compile time |
| Inner type methods | Not accessible directly on the wrapper |
| Solution | Implement `Deref` to auto-deref to inner type, or manually delegate methods |

### The Newtype Pattern's Other Uses

Beyond the orphan rule, newtypes are also used to:
- **Enforce type safety** — `Meters(u32)` vs `Millimeters(u32)` prevents mixing units
- **Hide implementation details** — expose a subset of an inner type's API
- **Add semantic meaning** — wrap a `String` as `HtmlEscaped` to track invariants

---

## Key Takeaways

| Concept | Summary |
|---|---|
| Associated types | One canonical type per trait impl; no call-site annotation needed |
| Default generic params | Simplify common case; allow customization when needed |
| Operator overloading | Implement `std::ops` traits (e.g. `Add`) on your types |
| Name disambiguation | Use `Trait::method(&val)` or `<Type as Trait>::fn()` for fully qualified calls |
| Supertraits | Declare dependencies between traits with `: OtherTrait` syntax |
| Newtype pattern | Thin wrapper to circumvent orphan rule; zero runtime cost |

# 20.3 - Advanced Types

## High-Level Overview

This section explores specialized features in Rust's type system:

1. **Newtype pattern** — type safety and encapsulation (revisited from 20.2 in a new light)
2. **Type aliases** — reducing repetition with `type` keyword synonyms
3. **The never type `!`** — representing functions that never return
4. **Dynamically Sized Types (DSTs)** — types whose size is only known at runtime

---

## Type Safety and Abstraction with the Newtype Pattern

Two primary benefits of the newtype pattern (beyond circumventing the orphan rule):

### 1. Static Type Safety

Wrapping the same primitive in different structs makes them incompatible at the type level:

```rust
struct Millimeters(u32);
struct Meters(u32);
```

The compiler will reject passing a `Meters` value where `Millimeters` is expected — catching unit-mismatch bugs at compile time instead of runtime.

### 2. Encapsulation / Hiding Implementation Details

```rust
// Internally backed by HashMap<i32, String>, but callers don't need to know that
struct People(HashMap<i32, String>);
```

You expose only the methods you choose — the inner type is an implementation detail.

## Type Aliases

Type aliases use the `type` keyword to give an existing type an alternative name:

```rust
fn main() {
    type Kilometers = i32;

    let x: i32 = 5;
    let y: Kilometers = 5;

    println!("x + y = {}", x + y);  // works — they're the same type
}
```

**Critical distinction from newtypes**: aliases are pure synonyms. The compiler treats `Kilometers` and `i32` as identical — no type-checking separation occurs. Use newtypes when you want enforcement; use aliases when you want convenience.

### Main Use Case: Reducing Repetition of Long Types

```rust
fn main() {
    type Thunk = Box<dyn Fn() + Send + 'static>;

    let f: Thunk = Box::new(|| println!("hi"));

    fn takes_long_type(f: Thunk) {
        // --snip--
    }

    fn returns_long_type() -> Thunk {
        // --snip--
        Box::new(|| ())
    }
}
```

Without the alias, `Box<dyn Fn() + Send + 'static>` would appear everywhere — tedious and error-prone to keep consistent.

### Common Pattern: `Result<T>` Aliases in the Standard Library

Many std modules alias `Result` to fix the error type for that module:

```rust
use std::fmt;

type Result<T> = std::result::Result<T, std::io::Error>;

pub trait Write {
    fn write(&mut self, buf: &[u8]) -> Result<usize>;
    fn flush(&mut self) -> Result<()>;

    fn write_all(&mut self, buf: &[u8]) -> Result<()>;
    fn write_fmt(&mut self, fmt: fmt::Arguments) -> Result<()>;
}
```

This keeps all signatures short and consistent while still being the full `std::result::Result<T, std::io::Error>` under the hood.

## The Never Type `!`

The never type `!` is the return type for functions that **never return** (called *diverging functions*):

```rust
fn bar() -> ! {
    panic!();
}
```

The type is called "never" because there is no value of that type — the function cannot complete normally.

### Why This Matters: Type Coercion in `match`

Every arm of a `match` must produce the same type. The never type solves the apparent mismatch when one arm diverges:

```rust
let guess: u32 = match guess.trim().parse() {
    Ok(num) => num,        // type: u32
    Err(_) => continue,   // type: ! — coerces to u32
};
```

`continue` has type `!`, which the compiler can coerce to any type — so the match arms unify to `u32`.

### `panic!` Uses the Same Trick

The `unwrap` method on `Option` works because `panic!` returns `!`:

```rust
impl<T> Option<T> {
    pub fn unwrap(self) -> T {
        match self {
            Some(val) => val,
            None => panic!("called `Option::unwrap()` on a `None` value"),
        }
    }
}
```

### Infinite Loops Also Have Type `!`

A `loop` that never breaks evaluates to `!`:

```rust
fn main() {
    print!("forever ");

    loop {
        print!("and ever ");
    }
}
```

## Dynamically Sized Types (DSTs) and the `Sized` Trait

**Dynamically Sized Types (DSTs)** are types whose size is only known at runtime, not at compile time. The most common example is `str`:

```rust
// INVALID — compiler can't allocate for unknown size
let s1: str = "Hello there!";
let s2: str = "How's it going?";
```

The compiler needs to know a type's size to allocate stack space for variables. `str` values can be any length, so this fails.

### Solution: Always Put DSTs Behind a Pointer

```rust
let s1: &str = "Hello there!";
let s2: &str = "How's it going?";
```

A `&str` is a **fat pointer** — two `usize` values on the stack:
1. A pointer to the start of the string data
2. The length

```
&str fat pointer
┌──────────────────┐
│  ptr  │  length  │  ← fixed size (2 × usize), known at compile time
└──────────────────┘
        │
        ▼
┌─────────────────────────────────┐
│  H  e  l  l  o  ,  w  o  r  l  │  ← heap/static data, variable length
└─────────────────────────────────┘
```

The same applies to `dyn Trait` objects — they're always used as `&dyn Trait` or `Box<dyn Trait>`.

### The `Sized` Trait

Rust automatically implements `Sized` for every type whose size is known at compile time. Generic functions implicitly require `Sized`:

```rust
// What you write:
fn generic<T>(t: T) { /* ... */ }

// What the compiler sees:
fn generic<T: Sized>(t: T) { /* ... */ }
```

This is why generic functions "just work" with normal types — they're all `Sized`.

### Relaxing the `Sized` Bound with `?Sized`

To allow a generic function to accept DSTs, use `?Sized`:

```rust
fn generic<T: ?Sized>(t: &T) {
    // --snip--
}
```

`?Sized` means "T may or may not be `Sized`." This is the only trait where `?` relaxation is supported. Note that the parameter must be a reference (`&T`) or pointer because we can't put an unsized value on the stack directly.

## Newtype vs. Type Alias — At a Glance

```
Newtype Pattern          Type Alias
────────────────         ──────────────────────────
struct Km(u32);          type Km = u32;

- Creates a NEW type     - Creates a SYNONYM only
- Type-checked strictly  - Compiler treats as same type
- No implicit coercion   - Can mix freely with original
- Zero runtime cost      - Zero runtime cost
- Hides inner API        - Exposes full inner API
```

## Key Takeaways

| Concept | Summary |
|---|---|
| Newtype (type safety) | Distinct wrapper type; compiler enforces separation |
| Newtype (encapsulation) | Hide implementation, expose controlled API |
| Type alias | Synonym only; reduces verbosity, no type safety gain |
| `Result<T>` alias pattern | Standard library idiom for module-specific error types |
| Never type `!` | No value exists; coerces to any type; used by `panic!`, `continue`, `loop` |
| DSTs | Size known only at runtime; must be behind `&`, `Box`, etc. |
| `Sized` trait | Implicit bound on all generics; auto-implemented for fixed-size types |
| `?Sized` | Opt out of `Sized` requirement to accept DSTs in generics |

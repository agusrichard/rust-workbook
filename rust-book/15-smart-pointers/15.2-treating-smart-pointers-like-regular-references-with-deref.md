# 15.2 - Treating Smart Pointers Like Regular References with the `Deref` Trait

## High-Level Overview

The `Deref` trait lets you customize the behavior of the **dereference operator** (`*`). By implementing `Deref`, a smart pointer can be treated exactly like a regular reference. This section builds from first principles — plain references, then `Box<T>`, then a custom smart pointer — to explain how and why `Deref` works, and introduces **deref coercion**, one of Rust's most ergonomic features.

---

## 1. Following a Reference to Its Value

The `*` operator dereferences a pointer to access the value it points to.

```rust
fn main() {
    let x = 5;
    let y = &x;

    assert_eq!(5, x);
    assert_eq!(5, *y);  // dereference y to get the i32
}
```

Without `*`, comparing `y` (a reference) to `5` (an integer) fails:

```
error[E0277]: can't compare `{integer}` with `&{integer}`
 --> src/main.rs:6:5
  |
6 |     assert_eq!(5, y);
  |     ^^^^^^^^^^^^^^^^ no implementation for `{integer} == &{integer}`
```

You must dereference first because `y` is `&i32`, not `i32`.

---

## 2. Using `Box<T>` Like a Reference

`Box<T>` supports `*` the same way a reference does:

```rust
fn main() {
    let x = 5;
    let y = Box::new(x);

    assert_eq!(5, x);
    assert_eq!(5, *y);  // works just like a reference
}
```

The only difference from Listing 15-6 is that `y` is a box pointing to a **copied** value on the heap, not a reference to `x` on the stack. The `*` behavior is identical.

---

## 3. Defining a Custom Smart Pointer

To understand how `Box<T>` achieves this, let's build our own:

```rust
struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(x: T) -> MyBox<T> {
        MyBox(x)
    }
}

fn main() {}
```

`MyBox<T>` is a **tuple struct** with one element. It has no dereference ability yet.

### Attempting to dereference without `Deref`:

```rust
fn main() {
    let x = 5;
    let y = MyBox::new(x);

    assert_eq!(5, x);
    assert_eq!(5, *y);  // compile error!
}
```

**Compiler error:**

```
error[E0614]: type `MyBox<{integer}>` cannot be dereferenced
  --> src/main.rs:14:19
   |
14 |     assert_eq!(5, *y);
   |                   ^^
```

Rust doesn't know how to dereference `MyBox<T>` because we haven't told it how.

---

## 4. Implementing the `Deref` Trait

To make `*` work on `MyBox<T>`, implement `std::ops::Deref`:

```rust
use std::ops::Deref;

struct MyBox<T>(T);

impl<T> MyBox<T> {
    fn new(x: T) -> MyBox<T> {
        MyBox(x)
    }
}

impl<T> Deref for MyBox<T> {
    type Target = T;

    fn deref(&self) -> &Self::Target {
        &self.0  // return a reference to the inner value
    }
}

fn main() {
    let x = 5;
    let y = MyBox::new(x);

    assert_eq!(5, x);
    assert_eq!(5, *y);  // now works!
}
```

### What `*y` actually does under the hood:

When Rust sees `*y`, it expands it to:
```rust
*(y.deref())
```

- `y.deref()` returns `&T` (a reference to the inner value)
- `*` then follows that reference

> **Why return `&T` and not `T`?** If `deref` returned the value directly, it would be **moved out** of `self`, which is usually not what you want. Returning a reference preserves ownership.

---

## 5. Implicit Deref Coercions

**Deref coercion** is an automatic conversion Rust applies when a reference to one type is passed where a reference to a different type is expected — as long as `Deref` is implemented for the conversion.

### Example setup:

```rust
fn hello(name: &str) {
    println!("Hello, {name}!");
}

fn main() {}
```

### Calling with `&MyBox<String>` — deref coercion in action:

```rust
fn main() {
    let m = MyBox::new(String::from("Rust"));
    hello(&m);  // &MyBox<String> → &String → &str  (automatic!)
}
```

Rust performs the following chain automatically at compile time:
1. `&MyBox<String>` → `&String` (via `MyBox`'s `Deref` impl: `deref()` returns `&String`)
2. `&String` → `&str` (via `String`'s built-in `Deref` impl)

No runtime cost — all resolved at compile time.

### Without deref coercion (manual):

```rust
fn main() {
    let m = MyBox::new(String::from("Rust"));
    hello(&(*m)[..]);  // tedious and noisy
}
```

- `*m` dereferences `MyBox<String>` to `String`
- `[..]` takes a full slice of it → `str`
- `&` borrows it → `&str`

Deref coercion eliminates all of this boilerplate.

---

## 6. Deref Coercion and Mutability

Rust supports three forms of deref coercion:

| From             | To               | Trait required            |
|------------------|------------------|---------------------------|
| `&T`             | `&U`             | `T: Deref<Target=U>`      |
| `&mut T`         | `&mut U`         | `T: DerefMut<Target=U>`   |
| `&mut T`         | `&U`             | `T: Deref<Target=U>`      |

**Key rule:** A mutable reference can coerce to an immutable reference, but **not the other way around**.

This respects Rust's borrowing rules:
- Converting `&mut T → &U` is safe: you're dropping mutability, which can't break anything
- Converting `&T → &mut U` would be unsafe: you'd be gaining mutability, potentially creating multiple mutable references

---

## Summary

| Concept | Description |
|---|---|
| `Deref` trait | Customizes the `*` operator for a type |
| `deref()` method | Returns `&Self::Target` — a reference to the inner value |
| `*y` expansion | Rust internally calls `*(y.deref())` |
| Deref coercion | Automatic `&T → &U` conversion at function call sites, resolved at compile time |
| Mutability coercion | `&mut T` can coerce to `&U`, but `&T` cannot coerce to `&mut U` |

The `Deref` trait is what makes smart pointers feel natural to use — you can pass a `&Box<String>` where a `&str` is expected, and Rust figures out the chain of conversions automatically.

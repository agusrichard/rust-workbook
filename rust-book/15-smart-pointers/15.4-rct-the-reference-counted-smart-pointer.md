# 15.4 - `Rc<T>`, the Reference Counted Smart Pointer

## Overview

`Rc<T>` is a smart pointer that enables **multiple ownership** of a single value through reference counting. The name `Rc` stands for *reference counting* — it keeps track of how many references exist to a value to determine when the value is no longer in use and can be safely cleaned up.

Use `Rc<T>` when a single value needs to be owned by multiple parts of a program simultaneously, and you cannot determine at compile time which part will finish using it last. A common example is graph data structures, where multiple edges might point to the same node.

> **Important**: `Rc<T>` is only for use in **single-threaded** scenarios. For multi-threaded reference counting, use `Arc<T>`.

---

## The Problem: Shared Ownership

Consider a cons list where two lists share ownership of a third:

```
b --> 3 \
          a --> 5 --> 10 --> Nil
c --> 4 /
```

With `Box<T>`, this is impossible — ownership is exclusive. The following code **fails to compile**:

```rust
enum List {
    Cons(i32, Box<List>),
    Nil,
}

use crate::List::{Cons, Nil};

fn main() {
    let a = Cons(5, Box::new(Cons(10, Box::new(Nil))));
    let b = Cons(3, Box::new(a)); // `a` is moved here
    let c = Cons(4, Box::new(a)); // ERROR: `a` was already moved
}
```

`Box<T>` enforces a single owner — once `a` is moved into `b`, it cannot be used again.

---

## The Solution: `Rc<T>`

Replace `Box<T>` with `Rc<T>` to allow shared ownership:

```rust
enum List {
    Cons(i32, Rc<List>),
    Nil,
}

use crate::List::{Cons, Nil};
use std::rc::Rc;

fn main() {
    let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
    let b = Cons(3, Rc::clone(&a));
    let c = Cons(4, Rc::clone(&a));
}
```

- `Rc::new(...)` wraps the value and starts the reference count at 1.
- `Rc::clone(&a)` increments the reference count and returns a new pointer to the same allocation — it does **not** do a deep copy.
- When `b` and `c` are created, the reference count for `a` goes from 1 to 3.

---

## `Rc::clone` vs `.clone()`

Rust's convention is to write `Rc::clone(&a)` rather than `a.clone()` when cloning an `Rc<T>`. Both do the same thing, but the explicit `Rc::clone` call makes it visually clear that this is a cheap reference-count increment — not an expensive deep copy. This helps readers distinguish performance characteristics at a glance.

---

## Observing the Reference Count

You can inspect the current reference count with `Rc::strong_count(&a)`. The count automatically decreases when an `Rc<T>` goes out of scope (via its `Drop` implementation):

```rust
fn main() {
    let a = Rc::new(Cons(5, Rc::new(Cons(10, Rc::new(Nil)))));
    println!("count after creating a = {}", Rc::strong_count(&a));
    // count after creating a = 1

    let b = Cons(3, Rc::clone(&a));
    println!("count after creating b = {}", Rc::strong_count(&a));
    // count after creating b = 2

    {
        let c = Cons(4, Rc::clone(&a));
        println!("count after creating c = {}", Rc::strong_count(&a));
        // count after creating c = 3
    }

    println!("count after c goes out of scope = {}", Rc::strong_count(&a));
    // count after c goes out of scope = 2
}
```

When `c` goes out of scope at the end of the inner block, the count drops from 3 to 2. When `b` and `a` eventually go out of scope, the count reaches 0 and the value is deallocated.

---

## Immutability Constraint

`Rc<T>` only allows **shared read-only access** to the data it contains. You cannot obtain a mutable reference through an `Rc<T>` directly, because allowing multiple mutable references to the same data could cause data races or consistency issues.

To combine shared ownership with interior mutability, see `RefCell<T>` (covered in the next section).

---

## Key Takeaways

| Feature | `Box<T>` | `Rc<T>` |
|---|---|---|
| Ownership | Single owner | Multiple owners |
| Thread safety | Yes | Single-threaded only |
| Mutability | Mutable | Immutable (shared) |
| Clone cost | Deep copy | Cheap (increments count) |

- Use `Rc<T>` when multiple parts of your program need read access to the same heap-allocated data.
- The value is dropped only when the reference count reaches zero.
- Use `Rc::clone(&x)` (not `x.clone()`) to signal that a cheap reference-count clone is happening.

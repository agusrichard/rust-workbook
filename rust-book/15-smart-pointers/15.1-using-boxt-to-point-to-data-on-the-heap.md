# 15.1 - Using `Box<T>` to Point to Data on the Heap

## High-Level Overview

`Box<T>` is the simplest smart pointer in Rust. It stores a value on the **heap** while the pointer itself lives on the **stack**. Beyond heap allocation, it adds no performance overhead and has no special extra capabilities — but it provides just enough indirection to solve problems that plain stack-allocated types cannot.

---

## When to Use `Box<T>`

There are three main situations where `Box<T>` is appropriate:

1. **Unknown size at compile time** — e.g., recursive types whose size can't be computed statically
2. **Transferring ownership of large data** — avoids copying large values on the stack; only the small pointer moves
3. **Owning a trait object** — when you care about a value implementing a trait rather than its concrete type (covered in Chapter 18)

---

## Basic Usage

```rust
fn main() {
    let b = Box::new(5);
    println!("b = {b}");
}
```

- `5` (an `i32`) is allocated on the **heap**
- `b` is a box (pointer) on the **stack** pointing to that heap value
- When `b` goes out of scope, both the box and the heap data are deallocated
- Output: `b = 5`

> Storing a single integer in a box like this isn't practical — a plain `let b = 5;` is better. The real power of `Box<T>` shows when enabling types that couldn't otherwise exist.

---

## Enabling Recursive Types with `Box<T>`

### The Problem: Recursive Types Have Infinite Size

A **recursive type** is one that holds a value of its own type. Rust must know a type's size at compile time, but a directly recursive type would require infinite space.

**Example — the cons list** (from Lisp/functional programming):

A cons list is a series of nested pairs:
```
(1, (2, (3, Nil)))
```

Each element holds a value and the rest of the list. `Nil` marks the end.

#### Broken implementation (won't compile):

```rust
enum List {
    Cons(i32, List),
    Nil,
}

use crate::List::{Cons, Nil};

fn main() {
    let list = Cons(1, Cons(2, Cons(3, Nil)));
}
```

#### Compiler error:

```
error[E0072]: recursive type `List` has infinite size
 --> src/main.rs:1:1
  |
1 | enum List {
  | ^^^^^^^^^
2 |     Cons(i32, List),
  |               ---- recursive without indirection
  |
help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle
  |
2 |     Cons(i32, Box<List>),
  |               ++++    +

error[E0391]: cycle detected when computing when `List` needs drop
```

The compiler tries to determine the size of `Cons`, which contains `List`, which contains `Cons`, which contains `List`... infinitely.

---

### How Rust Computes Enum Size (Non-Recursive Case)

For a regular enum like `Message`:

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}
```

Rust allocates space equal to the **largest variant**. This works because none of the variants refer back to `Message` itself.

For `List`, the same analysis loops forever — the compiler can't settle on a size.

---

### The Fix: Use `Box<T>` for Indirection

A `Box<T>` is always pointer-sized (known at compile time), regardless of what it points to. Wrapping the recursive part in a `Box` breaks the infinite size cycle:

#### Fixed implementation:

```rust
enum List {
    Cons(i32, Box<List>),
    Nil,
}

use crate::List::{Cons, Nil};

fn main() {
    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
}
```

Now:
- `Cons` holds an `i32` + a **pointer** (fixed size) to the next `List` on the heap
- `Nil` holds nothing
- The compiler can determine the size of `List`: `size_of::<i32>() + size_of::<Box<List>>()`

The actual list data lives on the heap; only the box pointers are on the stack/inline in the enum.

---

## Key Traits Behind `Box<T>`

| Trait   | What it enables                                                          |
|---------|--------------------------------------------------------------------------|
| `Deref` | Lets you treat a `Box<T>` like a regular reference (`*b` dereferences it) |
| `Drop`  | Automatically frees the heap data when the box goes out of scope         |

These two traits are the foundation for all smart pointer behavior covered in the rest of Chapter 15.

---

## Summary

- `Box<T>` = heap allocation + pointer on the stack
- No extra runtime cost beyond the indirection itself
- Solves the **recursive type** problem by providing a fixed-size pointer instead of embedding the type directly
- The cons list example (`List` enum) is the canonical demonstration
- In practice, prefer `Vec<T>` for list-like structures in Rust; cons lists are mainly illustrative
- `Box<T>` implements `Deref` and `Drop`, making it the simplest member of the smart pointer family

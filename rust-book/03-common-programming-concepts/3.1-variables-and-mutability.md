# Variables and Mutability

This chapter explores how Rust handles variable changes, explaining the differences between immutable variables, mutable variables, constants, and shadowing.

### Variables are Immutable by Default

In Rust, once a value is bound to a variable name, you cannot change that value by default. This is a safety feature to prevent bugs where one part of the code changes a value that another part expects to remain constant.

- **Attempting to reassign:** If you try to assign a new value to an immutable variable (e.g., `let x = 5; x = 6;`), the compiler will throw an error (`cannot assign twice to immutable variable`).

### Mutable Variables

If you need a variable to change, you must explicitly declare it as mutable using the `mut` keyword.

- **Syntax:** `let mut x = 5;`
- **Purpose:**
- Allows the value to be changed later (e.g., `x = 6;`).
- Clearly signals intent to future readers that this value will change.

### Constants

Constants are values bound to a name that **never** change. They differ from variables in several ways:

1. **Keyword:** Declared with `const` instead of `let`.
2. **No Mutability:** You cannot use `mut` with constants; they are always immutable.
3. **Type Annotation:** You must always annotate the type (e.g., `u32`).
4. **Scope:** Can be declared in any scope, including the global scope.
5. **Value:** Must be set to a constant expression, not a value computed at runtime.

**Example:**

```rust
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;

```

_Note: Naming convention for constants is all uppercase with underscores._

### Shadowing

Shadowing allows you to declare a new variable with the same name as a previous one. The new variable "overshadows" the previous one.

- **Syntax:** You repeat the `let` keyword (e.g., `let x = 5; let x = x + 1;`).
- **Benefits:**
- **Immutability:** The new variable is immutable (unless you add `mut` again), even though you modified the value during the shadowing process.
- **Type Changing:** You can change the _type_ of the value while keeping the same name (e.g., changing a String " " to a number `3`). This is not possible with `mut`, which enforces the original type.

**Shadowing Example:**

```rust
let x = 5;
let x = x + 1; // x is now 6
{
    let x = x * 2; // x is now 12 (inner scope)
}
// x is 6 again (outer scope)

```

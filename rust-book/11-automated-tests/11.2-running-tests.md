# 11.2 - Running Tests

## Overview

The `cargo test` command compiles code in test mode and executes the resulting test binary. By default, tests run in parallel with output capture enabled. Developers can customize this behavior through command-line options passed to either `cargo test` or the test binary itself.

---

## Command-Line Argument Structure

Arguments are split into two categories using the `--` separator:

- **Before `--`**: options for `cargo test` itself
- **After `--`**: options for the compiled test binary

Example:
```bash
cargo test -- --test-threads=1
```

---

## Running Tests in Parallel or Consecutively

**Default behavior:** Tests run simultaneously using threads for faster feedback.

**Problem:** Concurrent tests that share state (e.g., files, environment variables) may interfere with each other.

**Solution:** Use `--test-threads` to control parallelism:

```bash
cargo test -- --test-threads=1
```

Setting threads to `1` prevents parallel execution, eliminating interference at the cost of longer run times.

---

## Displaying Function Output

By default, output from passing tests (e.g., `println!`) is suppressed. Failed tests show their output alongside failure details.

To see output from **all** tests including passing ones:

```bash
cargo test -- --show-output
```

---

## Running Specific Tests

### Single Test by Name

```bash
cargo test one_hundred
```

Only the test named `one_hundred` runs; all others are filtered out.

### Multiple Tests by Substring

```bash
cargo test add
```

Runs all tests whose name contains `"add"`. Module names are part of the test identifier, so you can also filter by module name.

---

## Ignoring Expensive Tests

Use the `#[ignore]` attribute to exclude slow tests from regular runs:

```rust
#[test]
#[ignore]
fn expensive_test() {
    // code that takes an hour to run
}
```

**Run only ignored tests:**

```bash
cargo test -- --ignored
```

**Run all tests including ignored ones:**

```bash
cargo test -- --include-ignored
```

This lets you skip lengthy tests during routine development while retaining access to them when needed.

# 21.3 – Graceful Shutdown and Cleanup

## Overview

This section extends the multithreaded web server to shut down cleanly instead of dropping everything abruptly. The key goals are:

1. Signal worker threads to stop accepting new jobs.
2. Let each thread finish its **current** job before exiting.
3. Join all threads so no work is abandoned mid-flight.

Two Rust mechanisms drive the solution:
- The **`Drop` trait** — runs cleanup code when a value goes out of scope.
- **Channel semantics** — dropping the sender side of an `mpsc` channel causes all `recv()` calls on the receiver to return `Err`, which the workers use as a stop signal.

---

## The Problem with Naive Shutdown

The worker threads run an infinite `loop`, blocking on `recv()` waiting for jobs. If the `ThreadPool` is dropped without signalling them, calling `join()` would block forever because the threads never exit the loop.

A secondary ownership problem: `JoinHandle::join()` requires ownership of the handle, but in a `Drop` impl we only have `&mut self`, so we can't simply move out of `self.workers`.

---

## Step-by-Step Solution

### Step 1 – Fix the Ownership Problem with `Vec::drain`

The first attempt at `Drop` tries to iterate mutably and call `join()`, which the compiler rejects because you cannot move out of a mutable reference.

**Broken version (does not compile):**

```rust
impl Drop for ThreadPool {
    fn drop(&mut self) {
        for worker in &mut self.workers {
            println!("Shutting down worker {}", worker.id);
            worker.thread.join().unwrap(); // ❌ can't move out of `&mut`
        }
    }
}
```

**Fix – use `Vec::drain(..)` to consume ownership:**

```rust
impl Drop for ThreadPool {
    fn drop(&mut self) {
        for worker in self.workers.drain(..) {       // drain moves each Worker out
            println!("Shutting down worker {}", worker.id);
            worker.thread.join().unwrap();
        }
    }
}
```

`drain(..)` removes elements from the `Vec` and yields them by value, giving us the ownership needed for `join()`.

> **Problem remaining:** threads still loop forever waiting for jobs, so `join()` still blocks forever.

---

### Step 2 – Signal Threads to Stop via Channel Drop

The trick: wrap the sender in `Option<mpsc::Sender<Job>>`. During `Drop`, call `.take()` on it (replaces the `Some` with `None` and returns the inner sender), then immediately drop it. This closes the channel's sending side, causing all waiting `recv()` calls to return `Err`.

**Updated `ThreadPool` struct:**

```rust
pub struct ThreadPool {
    workers: Vec<Worker>,
    sender: Option<mpsc::Sender<Job>>,  // wrapped in Option
}
```

**Updated `new` — store `Some(sender)`:**

```rust
ThreadPool {
    workers,
    sender: Some(sender),
}
```

**Updated `execute` — unwrap through `as_ref()`:**

```rust
pub fn execute<F>(&self, f: F)
where
    F: FnOnce() + Send + 'static,
{
    let job = Box::new(f);
    self.sender.as_ref().unwrap().send(job).unwrap();
}
```

**Updated `Drop` — drop sender first, then join:**

```rust
impl Drop for ThreadPool {
    fn drop(&mut self) {
        drop(self.sender.take());   // closes the channel

        for worker in self.workers.drain(..) {
            println!("Shutting down worker {}", worker.id);
            worker.thread.join().unwrap();
        }
    }
}
```

Order matters: the sender must be dropped **before** joining, otherwise the workers never see the channel close.

---

### Step 3 – Update Worker Loop to Handle Channel Close

Change the worker from `unwrap()`-ing `recv()` (which would panic on `Err`) to a `match` that breaks out of the loop on error:

```rust
impl Worker {
    fn new(id: usize, receiver: Arc<Mutex<mpsc::Receiver<Job>>>) -> Worker {
        let thread = thread::spawn(move || {
            loop {
                let message = receiver.lock().unwrap().recv();

                match message {
                    Ok(job) => {
                        println!("Worker {id} got a job; executing.");
                        job();
                    }
                    Err(_) => {
                        println!("Worker {id} disconnected; shutting down.");
                        break;
                    }
                }
            }
        });

        Worker { id, thread }
    }
}
```

When the sender is dropped, `recv()` returns `Err`, the worker prints a message and breaks, and the thread exits — allowing `join()` to return immediately.

---

### Step 4 – Use `Option<JoinHandle>` for a Cleaner Final Version

The book's final version wraps the `JoinHandle` in `Option` too, using `if let Some(thread) = worker.thread.take()` in `Drop`. This avoids consuming `Worker` via `drain` and instead iterates mutably:

```rust
struct Worker {
    id: usize,
    thread: Option<thread::JoinHandle<()>>,
}
```

```rust
impl Drop for ThreadPool {
    fn drop(&mut self) {
        drop(self.sender.take());

        for worker in &mut self.workers {
            println!("Shutting down worker {}", worker.id);

            if let Some(thread) = worker.thread.take() {
                thread.join().unwrap();
            }
        }
    }
}
```

`Worker::new` then wraps the handle: `Worker { id, thread: Some(thread) }`.

## Demonstration – Limit to Two Requests

`src/main.rs` uses `.take(2)` on the incoming iterator so the server accepts exactly two connections and then drops the pool:

```rust
fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();
    let pool = ThreadPool::new(4);

    for stream in listener.incoming().take(2) {
        let stream = stream.unwrap();
        pool.execute(|| {
            handle_connection(stream);
        });
    }

    println!("Shutting down.");
}
```

When the loop ends, `pool` goes out of scope → `Drop` runs → sender dropped → workers receive `Err` → workers print "disconnected" → threads exit → `join()` returns → clean exit.

## Final Complete Code

### `src/main.rs`

```rust
use hello::ThreadPool;
use std::{
    fs,
    io::{BufReader, prelude::*},
    net::{TcpListener, TcpStream},
    thread,
    time::Duration,
};

fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();
    let pool = ThreadPool::new(4);

    for stream in listener.incoming().take(2) {
        let stream = stream.unwrap();

        pool.execute(|| {
            handle_connection(stream);
        });
    }

    println!("Shutting down.");
}

fn handle_connection(mut stream: TcpStream) {
    let buf_reader = BufReader::new(&stream);
    let request_line = buf_reader.lines().next().unwrap().unwrap();

    let (status_line, filename) = match &request_line[..] {
        "GET / HTTP/1.1" => ("HTTP/1.1 200 OK", "hello.html"),
        "GET /sleep HTTP/1.1" => {
            thread::sleep(Duration::from_secs(5));
            ("HTTP/1.1 200 OK", "hello.html")
        }
        _ => ("HTTP/1.1 404 NOT FOUND", "404.html"),
    };

    let contents = fs::read_to_string(filename).unwrap();
    let length = contents.len();

    let response =
        format!("{status_line}\r\nContent-Length: {length}\r\n\r\n{contents}");

    stream.write_all(response.as_bytes()).unwrap();
}
```

### `src/lib.rs`

```rust
use std::{
    sync::{Arc, Mutex, mpsc},
    thread,
};

pub struct ThreadPool {
    workers: Vec<Worker>,
    sender: Option<mpsc::Sender<Job>>,
}

type Job = Box<dyn FnOnce() + Send + 'static>;

impl ThreadPool {
    /// Create a new ThreadPool.
    ///
    /// The size is the number of threads in the pool.
    ///
    /// # Panics
    ///
    /// The `new` function will panic if the size is zero.
    pub fn new(size: usize) -> ThreadPool {
        assert!(size > 0);

        let (sender, receiver) = mpsc::channel();

        let receiver = Arc::new(Mutex::new(receiver));

        let mut workers = Vec::with_capacity(size);

        for id in 0..size {
            workers.push(Worker::new(id, Arc::clone(&receiver)));
        }

        ThreadPool {
            workers,
            sender: Some(sender),
        }
    }

    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static,
    {
        let job = Box::new(f);

        self.sender.as_ref().unwrap().send(job).unwrap();
    }
}

impl Drop for ThreadPool {
    fn drop(&mut self) {
        drop(self.sender.take());

        for worker in &mut self.workers {
            println!("Shutting down worker {}", worker.id);

            if let Some(thread) = worker.thread.take() {
                thread.join().unwrap();
            }
        }
    }
}

struct Worker {
    id: usize,
    thread: Option<thread::JoinHandle<()>>,
}

impl Worker {
    fn new(id: usize, receiver: Arc<Mutex<mpsc::Receiver<Job>>>) -> Worker {
        let thread = thread::spawn(move || {
            loop {
                let message = receiver.lock().unwrap().recv();

                match message {
                    Ok(job) => {
                        println!("Worker {id} got a job; executing.");

                        job();
                    }
                    Err(_) => {
                        println!("Worker {id} disconnected; shutting down.");
                        break;
                    }
                }
            }
        });

        Worker {
            id,
            thread: Some(thread),
        }
    }
}
```

## Shutdown Sequence Diagram

```
main() ends
    │
    └─► pool dropped → Drop::drop() called
            │
            ├─ 1. drop(self.sender.take())
            │       └─ channel sender closed
            │
            ├─ 2. for each worker: worker.thread.take() → join()
            │
Worker threads (looping on recv()):
    recv() returns Err  ←── channel closed
        │
        └─ match Err(_) → print "disconnected" → break
                │
                └─ thread exits → join() returns ✓
```

## Key Concepts

| Concept | Role in this section |
|---|---|
| `Drop` trait | Runs shutdown logic when `ThreadPool` goes out of scope |
| `Option::take()` | Extracts a value from `Option`, leaving `None` — gives ownership without moving out of `&mut self` |
| `mpsc` channel close semantics | Dropping the sender makes `recv()` return `Err` on all receivers |
| `Vec::drain(..)` / `Option<JoinHandle>` | Two ways to obtain ownership of the `JoinHandle` needed for `join()` |
| `.take(2)` on iterator | Limits how many connections are processed before graceful shutdown begins |

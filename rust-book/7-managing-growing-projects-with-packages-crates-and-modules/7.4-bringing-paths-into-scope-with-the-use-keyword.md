# Bringing Paths Into Scope with the `use` Keyword

This section of "The Rust Programming Language" explains how the `use` keyword simplifies referring to items in Rust's module system by bringing paths into the current scope. It covers idiomatic usage, handling name conflicts, re-exporting with `pub use`, and using external packages.

## High-level overview

The `use` keyword in Rust allows developers to create shortcuts to module paths, reducing repetition and improving code readability. It's analogous to creating symbolic links in a filesystem, making items accessible with shorter names within a specific scope. The chapter details best practices for using `use` with functions, structs, and enums, and introduces advanced features like `as` for renaming and `pub use` for re-exporting.

## Key points and main arguments

*   **Simplifying Paths**: The `use` keyword allows for shorter, more convenient access to items (functions, structs, enums) defined in modules by bringing their paths into the current scope.
*   **Scope of `use`**: A `use` statement only applies to the specific scope in which it is declared. Moving code into a child module requires either moving the `use` statement or using `super::` to reference the shortcut from the parent module.
*   **Idiomatic `use` for Functions vs. Structs/Enums**:
    *   For functions, it's idiomatic to bring the parent module into scope (e.g., `use crate::front_of_house::hosting;`) and then call the function using `hosting::add_to_waitlist()`. This clarifies that the function is not locally defined.
    *   For structs, enums, and other items, it's idiomatic to bring the full path into scope (e.g., `use std::collections::HashMap;`).
*   **Handling Name Conflicts**:
    *   When bringing two items with the same name into scope from different parent modules, you can specify the parent modules when using them (e.g., `fmt::Result` and `io::Result`).
    *   Alternatively, the `as` keyword can be used to provide a new local name (alias) for one of the conflicting types (e.g., `use std::io::Result as IoResult;`).
*   **Re-exporting with `pub use`**: Combining `pub` and `use` (e.g., `pub use crate::front_of_house::hosting;`) makes an item available for external code to use as if it were defined in the current scope. This is useful for structuring internal code differently from its public API.
*   **Using External Packages**: To use external packages (crates), they must be listed in `Cargo.toml` and then brought into scope using `use` statements. The standard library (`std`) is also a crate, and its items are brought into scope similarly.
*   **Nested Paths**: Multiple items from the same crate or module can be brought into scope using nested paths with curly brackets (e.g., `use std::{cmp::Ordering, io};`). The `self` keyword can be used to include the parent module itself in a nested path (e.g., `use std::io::{self, Write};`).
*   **Glob Operator (`*`)**: The glob operator (`*`) can bring all public items from a path into scope (e.g., `use std::collections::*;`). However, its use should be cautious as it can make code harder to read and may lead to naming conflicts upon dependency updates.

## Significant conclusions

The `use` keyword is fundamental for managing module paths in Rust, significantly improving code clarity and reducing verbosity. Adhering to idiomatic `use` patterns, understanding scope, and utilizing features like `as` and `pub use` are crucial for writing maintainable and well-structured Rust code. While powerful, the glob operator should be used judiciously to avoid potential issues.

## Code snippets

**Idiomatic use for a function**
```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}

use crate::front_of_house::hosting;

pub fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

**Idiomatic use for a struct**
```rust
use std::collections::HashMap;

fn main() {
    let mut map = HashMap::new();
    map.insert(1, 2);
}
```

**Handling name conflicts with parent modules**
```rust
use std::fmt;
use std::io;

fn function1() -> fmt::Result {
    Ok(())
}

fn function2() -> io::Result<()> {
    Ok(())
}
```

**Handling name conflicts with the `as` keyword**
```rust
use std::fmt::Result;
use std::io::Result as IoResult;

fn function1() -> Result {
    Ok(())
}

fn function2() -> IoResult<()> {
    Ok(())
}
```

**Re-exporting with `pub use`**
```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}

pub use crate::front_of_house::hosting;

pub fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

**Nested paths**
```rust
use std::{cmp::Ordering, io};
```

**Nested paths with `self`**
```rust
use std::io::{self, Write};
```

**Glob operator**
```rust
use std::collections::*;
```

# Control Scope and Privacy with Modules

This section of the Rust book focuses on the module system, which includes modules, paths, the `use` keyword, and the `pub` keyword. It explains how to organize code, control privacy (public vs. private), and manage namespaces.

## Modules Cheat Sheet

The page provides a quick reference for how modules work in Rust:

1. **Crate Root**: The compiler starts at the crate root (`src/lib.rs` for libraries or `src/main.rs` for binaries).
2. **Declaring Modules**: Modules are declared with `mod module_name;`. The compiler looks for the code in:
* Inline (within curly brackets `{}`).
* `src/module_name.rs`.
* `src/module_name/mod.rs`.


3. **Submodules**: Submodules declared in files other than the root are looked for in a directory named after the parent.
4. **Paths**: You can refer to code using paths (e.g., `crate::garden::vegetables::Asparagus`).
5. **Privacy**: Code is **private** by default. Use `pub mod` and `pub` before items to make them public.
6. **`use` Keyword**: Creates shortcuts to items to avoid repeating long paths.

### Example: The "Backyard" Crate

A binary crate named `backyard` illustrates these rules with the following file structure:

```text
backyard
├── Cargo.lock
├── Cargo.toml
└── src
    ├── garden
    │   └── vegetables.rs
    ├── garden.rs
    └── main.rs

```

**`src/main.rs`**
The root file declares the `garden` module and uses the `Asparagus` type.

```rust
use crate::garden::vegetables::Asparagus;

pub mod garden;

fn main() {
    let plant = Asparagus {};
    println!("I'm growing {plant:?}!");
}

```

**`src/garden.rs`**
This file declares the `vegetables` submodule.

```rust
pub mod vegetables;

```

**`src/garden/vegetables.rs`**
This file contains the actual code for the submodule.

```rust
#[derive(Debug)]
pub struct Asparagus {}

```

## Grouping Related Code in Modules

Modules organize code for readability and reuse. They also define privacy boundaries—items inside a module are private implementation details by default.

### Example: The "Restaurant" Library

The book uses a restaurant analogy to demonstrate nesting.

* **Front of House**: Hosting (seating customers), Serving (taking orders).
* **Back of House**: Kitchen, Chefs.

To create this library:
`cargo new restaurant --lib`

**`src/lib.rs` (Listing 7-1)**
This defines the module structure without implementation details.

```rust
mod front_of_house {
    mod hosting {
        fn add_to_waitlist() {}

        fn seat_at_table() {}
    }

    mod serving {
        fn take_order() {}

        fn serve_order() {}

        fn take_payment() {}
    }
}

```

## The Module Tree

Just like a filesystem, Rust modules form a tree structure. `src/main.rs` and `src/lib.rs` act as the root (implicitly named `crate`).

**Module Tree Visualization (Listing 7-2)**

```text
crate
└── front_of_house
    ├── hosting
    │   ├── add_to_waitlist
    │   └── seat_at_table
    └── serving
        ├── take_order
        ├── serve_order
        └── take_payment

```

* **Parent/Child**: `hosting` is a child of `front_of_house`.
* **Siblings**: `hosting` and `serving` are siblings.

This structure allows developers to easily navigate definitions and keep related code grouped together.

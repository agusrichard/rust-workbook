# Paths for Referring to an Item in the Module Tree

## High-level overview
This section of "The Rust Programming Language" explains how to navigate and refer to items within Rust's module tree using paths. It covers absolute and relative paths, the role of the `pub` keyword in controlling visibility, and specific considerations for making structs and enums public. The core concept is that Rust's module system, by default, enforces privacy, requiring explicit `pub` declarations to expose items for use by other modules.

## Key points and main arguments
*   **Paths in Rust:** Paths are used to locate items (functions, structs, enums, modules, constants) within the module tree, similar to file paths in a filesystem.
*   **Absolute Paths:**
    *   Start from the crate root.
    *   For external crates, they begin with the crate name.
    *   For the current crate, they start with the literal `crate`.
    *   Example: `crate::front_of_house::hosting::add_to_waitlist();`
*   **Relative Paths:**
    *   Start from the current module.
    *   Can use `self`, `super`, or an identifier in the current module.
    *   Example: `front_of_house::hosting::add_to_waitlist();`
    *   `super` allows starting a relative path from the parent module, similar to `..` in a filesystem.
*   **Privacy by Default:**
    *   All items in Rust are private to their parent modules by default.
    *   Items in a parent module cannot use private items inside child modules.
    *   Child modules, however, can use items in their ancestor modules.
    *   This default privacy helps in hiding implementation details and managing changes without breaking external code.
*   **The `pub` Keyword:**
    *   Used to make items public, allowing them to be accessed by other modules.
    *   Making a module `pub` only makes the module itself public, not its contents. Each item within a public module still needs its own `pub` declaration to be public.
*   **Public Structs and Enums:**
    *   When a `struct` is made `pub`, its fields remain private by default. Individual fields must be explicitly marked `pub` to be accessible.
    *   If a `pub` struct has private fields, it often needs a public associated function (e.g., a constructor) to allow instances to be created from outside the module.
    *   When an `enum` is made `pub`, all of its variants automatically become public.

## Significant conclusions
*   Rust's module system prioritizes encapsulation and information hiding by making items private by default.
*   Developers must explicitly use the `pub` keyword to expose parts of their code that should be part of a public API.
*   Choosing between absolute and relative paths depends on the expected refactoring and movement of code; absolute paths are generally preferred for stability when definitions and calls might move independently.
*   When designing libraries, it's a best practice to define the module tree in `src/lib.rs` and have the binary crate use the library's public API, treating it like an external crate.

## Code snippets

**Example of Absolute and Relative Paths with Privacy Issues:**
```rust
mod front_of_house {
    mod hosting {
        fn add_to_waitlist() {}
    }
}

pub fn eat_at_restaurant() {
    // Absolute path
    crate::front_of_house::hosting::add_to_waitlist(); // This will cause an error: module `hosting` is private
    // Relative path
    front_of_house::hosting::add_to_waitlist(); // This will cause an error: module `hosting` is private
}
```

**Fixing Privacy with `pub`:**
```rust
mod front_of_house {
    pub mod hosting { // Made hosting public
        pub fn add_to_waitlist() {} // Made add_to_waitlist public
    }
}

pub fn eat_at_restaurant() {
    // Absolute path
    crate::front_of_house::hosting::add_to_waitlist(); // Now compiles
    // Relative path
    front_of_house::hosting::add_to_waitlist(); // Now compiles
}
```

**Using `super` for Relative Paths:**
```rust
fn deliver_order() {}

mod back_of_house {
    fn fix_incorrect_order() {
        cook_order();
        super::deliver_order(); // Calls deliver_order in the parent module (crate root)
    }
    fn cook_order() {}
}
```

**Public Struct with Private Fields:**
```rust
mod back_of_house {
    pub struct Breakfast {
        pub toast: String, // Public field
        seasonal_fruit: String, // Private field
    }

    impl Breakfast {
        pub fn summer(toast: &str) -> Breakfast {
            Breakfast {
                toast: String::from(toast),
                seasonal_fruit: String::from("peaches"),
            }
        }
    }
}

pub fn eat_at_restaurant() {
    let mut meal = back_of_house::Breakfast::summer("Rye");
    meal.toast = String::from("Wheat"); // Allowed: toast is public
    // meal.seasonal_fruit = String::from("blueberries"); // Error: seasonal_fruit is private
}
```

**Public Enum:**
```rust
mod back_of_house {
    pub enum Appetizer { // Making enum public makes all variants public
        Soup,
        Salad,
    }
}

pub fn eat_at_restaurant() {
    let order1 = back_of_house::Appetizer::Soup;
    let order2 = back_of_house::Appetizer::Salad;
}
```

# Separating Modules into Different Files

## High-Level Overview
This chapter of "The Rust Programming Language" explains how to organize Rust code by separating modules into different files to improve navigability and manage large projects. It details the process of extracting module definitions from a single crate root file into individual files and directories, maintaining the module tree structure. The article also touches upon older, still-supported file path conventions and their potential drawbacks.

## Key Points and Main Arguments
*   **Module Separation:** Rust allows developers to move module definitions into separate files to enhance code organization and readability, especially as modules grow in size.
*   **File Naming Conventions:** For a module declared in `src/lib.rs` (or `src/main.rs`), Rust expects its code in `src/<module_name>.rs`.
*   **Nested Modules:** For child modules, a new directory named after the parent module is created, and the child module's file is placed within it (e.g., `src/front_of_house/hosting.rs` for a `hosting` module inside `front_of_house`).
*   **`mod` Keyword:** The `mod` keyword declares a module and tells Rust where to find its code; it is not an "include" operation like in other languages.
*   **Older File Paths:** Rust also supports an older style where module code can be in `src/<module_name>/mod.rs` or `src/<parent_module>/<child_module>/mod.rs`. While still supported, this can lead to many `mod.rs` files, which might be confusing.
*   **Module Tree Preservation:** Separating modules into different files does not alter the module tree or the functionality of `pub use` statements.

## Code Snippets

### `src/lib.rs`
```rust
mod front_of_house;

pub use crate::front_of_house::hosting;

pub fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

### `src/front_of_house.rs`
```rust
pub mod hosting;
```

### `src/front_of_house/hosting.rs`
```rust
pub fn add_to_waitlist() {}
```

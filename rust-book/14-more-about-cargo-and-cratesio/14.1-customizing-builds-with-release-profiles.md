# 14.1 - Customizing Builds with Release Profiles

## High-Level Overview

Release profiles in Rust are predefined, customizable compilation profiles that give developers control over how code is compiled. Cargo has two main built-in profiles — `dev` and `release` — each with different default settings suited for their respective use cases. Developers can override these defaults in `Cargo.toml` to fine-tune compilation behavior.

---

## The Two Default Profiles

Cargo uses different profiles depending on the command run:

| Command                  | Profile Used | Description                              |
|--------------------------|--------------|------------------------------------------|
| `cargo build`            | `dev`        | Fast to compile, includes debug info     |
| `cargo build --release`  | `release`    | Slower to compile, optimized for runtime |

You can see which profile is active in the build output:

```
$ cargo build
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.00s

$ cargo build --release
    Finished `release` profile [optimized] target(s) in 0.32s
```

---

## Default Profile Settings

Each profile has a set of default values. Cargo applies these even if you don't add any `[profile.*]` sections to `Cargo.toml`. The defaults for the `opt-level` setting are:

```toml
[profile.dev]
opt-level = 0

[profile.release]
opt-level = 3
```

---

## The `opt-level` Setting

`opt-level` controls how many compiler optimizations are applied to the compiled code. It accepts values from `0` to `3`:

| `opt-level` | Optimizations     | Compile Speed | Runtime Speed |
|-------------|-------------------|---------------|---------------|
| `0`         | None              | Fastest       | Slowest       |
| `1`         | Basic             | Moderate      | Moderate      |
| `2`         | More              | Slower        | Faster        |
| `3`         | Maximum           | Slowest       | Fastest       |

**Why `dev` defaults to `0`**: During development you recompile frequently, so fast compile times matter more than runtime performance.

**Why `release` defaults to `3`**: Release builds are compiled once but run many times, so maximum runtime speed is worth the longer compile time.

---

## Overriding Default Settings

You can override any profile setting by adding a `[profile.*]` section to your project's `Cargo.toml`. Any value you set overrides the default.

### Example: Increase optimization in dev builds

```toml
[profile.dev]
opt-level = 1
```

This applies more optimization than the default `0` during development — a middle ground between fast compile times and some runtime performance.

---

## Key Takeaways

- Cargo has two main profiles: **`dev`** (for `cargo build`) and **`release`** (for `cargo build --release`).
- Each profile has sensible defaults — `dev` prioritizes compile speed, `release` prioritizes runtime speed.
- Override settings by adding `[profile.dev]` or `[profile.release]` sections to `Cargo.toml`.
- Only the settings you explicitly set override the defaults; everything else uses Cargo's built-in values.
- The full list of configurable settings is available in [Cargo's documentation](https://doc.rust-lang.org/cargo/reference/profiles.html).

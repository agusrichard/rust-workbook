# 8.3 - Storing Keys with Associated Values in Hash Maps

## Overview

`HashMap<K, V>` is the last of the three common collections covered in Chapter 8. It stores mappings from keys of type `K` to values of type `V` using a hashing function. Hash maps are useful when you want to look up data by a key (of any type) rather than by a numeric index.

---

## Creating a New Hash Map

Hash maps are not in the prelude, so they must be imported:

```rust
use std::collections::HashMap;

let mut scores = HashMap::new();

scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Yellow"), 50);
```

- Data is stored on the **heap**.
- Hash maps are **homogeneous**: all keys must be the same type, and all values must be the same type.

---

## Accessing Values

Use the `get` method to retrieve a value by key:

```rust
let team_name = String::from("Blue");
let score = scores.get(&team_name).copied().unwrap_or(0);
```

- `get` returns `Option<&V>`.
- `.copied()` converts `Option<&i32>` to `Option<i32>`.
- `.unwrap_or(0)` returns `0` if the key doesn't exist.

Iterate over all key-value pairs:

```rust
for (key, value) in &scores {
    println!("{key}: {value}");
}
```

---

## Hash Maps and Ownership

- Types implementing `Copy` (e.g., `i32`) are **copied** into the map.
- Owned types like `String` are **moved** — the map becomes the owner.

```rust
let field_name = String::from("Favorite color");
let field_value = String::from("Blue");

let mut map = HashMap::new();
map.insert(field_name, field_value);
// field_name and field_value are invalid here
```

If references are inserted, they must remain valid for at least as long as the hash map is valid.

---

## Updating a Hash Map

A hash map can only have **one value per key**. There are three strategies for updates:

### 1. Overwrite an Existing Value

```rust
scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Blue"), 25);
// {"Blue": 25}
```

### 2. Insert Only If Key Doesn't Exist (`entry` + `or_insert`)

```rust
scores.entry(String::from("Yellow")).or_insert(50);
scores.entry(String::from("Blue")).or_insert(50);
// Blue retains its original value (10)
```

`entry` returns an `Entry` enum; `or_insert` returns a mutable reference to the value (existing or newly inserted).

### 3. Update Based on Old Value

A classic example — counting word occurrences:

```rust
use std::collections::HashMap;

let text = "hello world wonderful world";
let mut map = HashMap::new();

for word in text.split_whitespace() {
    let count = map.entry(word).or_insert(0);
    *count += 1;
}

println!("{map:?}");
// {"hello": 1, "world": 2, "wonderful": 1}
```

`or_insert` returns `&mut V`, which is dereferenced with `*` to mutate the value in place.

---

## Hashing Functions

By default, `HashMap` uses **SipHash**, which provides resistance to denial-of-service (DoS) attacks targeting hash table collisions. It is not the fastest algorithm, but the security tradeoff is worthwhile.

To use a faster hasher, supply a type implementing the `BuildHasher` trait. Many alternatives are available on [crates.io](https://crates.io).

---

## Key Takeaways

- Use `HashMap::new()` and `insert` to create and populate a hash map.
- Use `get` for single-key lookups and `for` loops for iteration.
- Owned values are moved into the map; `Copy` types are copied.
- The `entry` API provides ergonomic conditional insertion and in-place mutation.
- Default hasher is SipHash — secure but swappable for performance-sensitive use cases.
